# 주간 전문가 패널 평가

목적: 개발자 스스로는 안 보이는 결함을, **서로 다른 직업적 관점 4개**로 매주 같은 기준으로 잡아낸다.
회차가 쌓이면 점수 추이가 곧 제품 개선의 증거가 된다.

대상: `https://naechaget.co.kr` (경매로 내차GET)
산출물: `docs/reviews/YYYY-MM-DD.md` · 스크린샷 `screenshots/weekly/YYYY-MM-DD/`

## 패널 4인과 배점

| 에이전트 | 역할 | 무엇을 보는가 |
|---|---|---|
| `usedcar-expert` | 중고차 전문가 | 상태 진단·가치 산정 30 / 맞춤 컨설팅 25 / 정보 투명성 30 / 사후 절차 15 |
| `app-design-expert` | 앱 디자인 전문가 | 정보 설계 30 / 신뢰 장치 25 / 안심 가이드 25 / 개인화 20 |
| `auction-expert` | 경매 전문가 | 가격 발견 30 / 등급화 25 / 유통 20 / 법적 클로징 25 |
| `app-qa-auditor` | 앱 품질 전문가 | 데이터 무결성 30 / 응답·안정성 20 / 크로스플랫폼 25 / 보안 25 |

공통 제약과 제품 범위는 `.claude/agents/_panel-context.md` 에 있고, 각 에이전트 정의 안에도 복사돼 있다.
**핵심**: 이 앱은 중고차 매매앱이 아니라 법원경매 분석 도구다. 결제·로그인·채팅·실시간 입찰이
없는 것은 결함이 아니라 설계 결정이므로 감점하지 않는다.

## 절차

### 1) 화면 캡처
```
PYTHONIOENCODING=utf-8 python scripts/capture_weekly_screens.py
```
`screenshots/weekly/<오늘>/` 에 8개 화면 × 모바일(390)·데스크톱(1440) = 16장이 생긴다.
디자인 전문가는 이걸 눈으로 보고 채점하므로 **캡처를 건너뛰지 말 것**.

> `screenshots/` 는 `.gitignore` 대상이라 저장소에 올라가지 않는다(주당 약 4.6MB).
> 회차 간 **시각적** 비교는 같은 기기에서 돌렸을 때만 가능하고, 클라우드 루틴은 매번 새로 찍는다.
> 점수와 지적은 리포트에 남으므로 추이 비교 자체에는 지장이 없다.

### 2) 전문가 4인 동시 실행
Agent 도구로 **네 개를 한 메시지에 담아** 병렬로 띄운다. 각 프롬프트에 넣을 것:
- 오늘 날짜와 회차(첫 회차인지, 몇 회차인지)
- 스크린샷 경로와 파일명 규칙
- 그 역할이 반드시 열어봐야 할 스크린샷 목록
- "정의된 반환 형식의 마크다운만 반환하고 파일은 쓰지 마라"

> ⚠️ 새로 만든 에이전트는 **세션 시작 시에만 등록**된다. `Agent type not found` 가 나면
> `subagent_type: general-purpose` 로 띄우고 프롬프트 첫 줄에
> "먼저 `.claude/agents/<이름>.md` 를 Read로 읽고 그 정의대로 행동하라"를 넣는다. 결과는 동일하다.

### 3) 종합 리포트 작성
네 결과를 받아 `docs/reviews/<오늘>.md` 에 아래 순서로 쓴다.
1. **한 줄 결론** — 이번 주 가장 아픈 것 하나.
2. **점수판** — 4인 총점과 항목별 점수, 지난 회차 대비 증감(`docs/reviews/` 의 직전 파일에서 읽는다).
3. **합의 지적** — 둘 이상이 같은 문제를 지적했으면 최상단에 묶는다. 여기가 진짜 우선순위다.
4. **역할별 지적 원문** — 4인 반환 마크다운 그대로.
5. **실행 백로그** — 지적을 `[P0]/[P1]/[P2]`로 분류하고, 각 항목에 담당 영역과 예상 작업을 붙인다.
   제약 위반 제안(엔카·보배 출처 노출, 데이터 추정 채우기)은 **여기서 걸러 폐기 사유를 적는다.**
6. **미해결 이월** — 지난 회차 백로그 중 아직 안 된 것.

### 4) 마무리
- `docs/changelog.md` 에 한 줄 기록.
- 커밋: `docs(주간평가): N회차 — 총점 A/B/C/D, 합의 지적 N건`
- P0가 있으면 사용자에게 **그것만** 요약해 보고한다. 리포트 전체를 대화에 붙여넣지 않는다.

## 규칙
- **점수를 부풀리지 않는다.** 후한 리포트는 쓸모가 없다. 내려간 항목은 이유를 적는다.
- **근거 없는 지적은 싣지 않는다.** 각 지적에 URL·스크린샷 파일명·측정값 중 하나는 있어야 한다.
- QA 전문가에게 **부하 테스트·쓰기 요청을 시키지 않는다.** 읽기 검증만.
- 리포트는 사람이 읽는 문서다. 표와 짧은 문장으로 쓰고, 코드 덩어리를 붙여넣지 않는다.
