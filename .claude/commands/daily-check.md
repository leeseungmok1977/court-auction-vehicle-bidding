---

Steward로서 **일간 점검**을 수행한다. 오늘 이상 징후가 있는지 보고, 있으면 원인을 밝힌다.

## 1. 먼저 직접 확인한다 (에이전트를 부르기 전에)

- 가장 최근 `docs/daily-reports/*.md` 의 `## 방문자` 표 — 방문자·1페이지 이탈·3페이지 이상
- 정기 작업 성패(매일 갱신·SSL·터널). **0건 단계를 성공으로 읽지 않는다.**
- 운영 헬스: `https://naechaget.co.kr/` 응답, `systemctl is-active naechaget`

## 2. 이상 징후 판단 기준

아래 중 하나라도 걸리면 **원인을 밝힌다.**

| 신호 | 기준 |
|---|---|
| 방문자 급감 | 직전 7일 평균 대비 −40% 이하 |
| 이탈 급증 | 1페이지 이탈이 직전 대비 +15%p 이상 |
| 추천 0대 | '지금 입찰 추천'과 '실사용 추천'이 동시에 0 |
| 수집 중단 | 매일 갱신이 실패했거나 시세 조회가 차단됨 |
| 정확도 이상 | 예측 오차가 직전 대비 ±3%p 넘게 움직임 |

## 3. 이상이 있으면 지시한다

`insight` 에게 [작업 지시서] 형식으로 원인 분석을 맡긴다. 결과는 `reports/` 에 남기게 하고,
**받은 뒤 내가 코드·DB·로그로 재현한 다음** 오너에게 올린다.

## 4. 보고

표준 보고 형식(`[요약] [지표] [진단] [제안] [승인 요청]`)으로 짧게 낸다.
**이상이 없으면 "이상 없음"과 핵심 수치 세 줄이면 충분하다** — 길게 쓰지 않는다.

> 자동 생성되는 일일 리포트(매일 12:00)와 중복 작업을 하지 마라. 그 파일을 **읽고 판단하는 것**이
> 이 명령의 일이다.
