## 총괄 재검증 — 패널 지적이 사실인가

패널 리포트의 규칙대로, 화면만 보고 낸 지적을 **코드·DB·프로덕션 응답으로 다시 확인했다.**
결과가 절반은 뒤집혔다.

| 패널 지적 (인원·심각도) | 재검증 결과 |
|---|---|
| **산출 로직 2·3단계 값이 동일** (4명 · 5) | **화면은 사실, 그러나 계산 버그가 아니다.** 세 쌍의 요율이 우연히 같다 — 수리비 기본 50만원 == 이전 30만+탁송 20만 = 50만원 · 사고감가율 0.15 == 목표마진율 0.15 · 리스크프리미엄율 0.07 == 취득세율 0.07. 실측(`2026타경51038_1`): 2단계 5,065,000 = 3단계 5,065,000, 구성 값도 쌍쌍이 일치. **두 줄 모두 개별로는 맞다.** 화면에 요율과 기준이 없어 복사 오류로 읽힐 뿐이다 → 각 항목에 요율·기준을 병기하면 해소된다. |
| **취득세가 1,379,000과 1,750,000 두 값** (2명 · 4) | **둘 다 맞다.** 재판매 상한가의 취득세는 **기준시세**×7%, 06 총 취득원가의 취득세는 **낙찰가**×7%다. 서로 다른 것을 재는데 라벨에 기준이 없다. |
| **화물차에 승용 7% 취득세 고정** (2명 · 5) | **사실.** `USE_TAX_RATE=0.07`·`acquisition_tax_rate=0.07` 단일값이고 차종·용도 분기가 없다. 라벨은 '비영업용 승용 7% · 낙찰가 연동'. 화물·영업용은 세율이 다르므로 **총액이 틀릴 수 있다.** |
| **기일 시각이 지난 물건이 '유찰 대기'** (2명 · 4) | **사실.** `bid_state`가 날짜만 비교한다(`sale_date < today`). DB에 `sale_time`(10:00)이 있는데 쓰지 않아, 기일 당일 오후에도 앞으로 갈 일처럼 표시된다. |
| **예상낙찰가가 최저매각가와 같다** (2명 · 4) | **사실.** 이 물건은 예상 25,000,000 = 최저매각가 25,000,000이고, 소프트캡(22,800,000)보다 위다. 법원 하한에 걸린 값이지 예측값이 아닌데 카드에 그 사정이 없다. |
| **리포트 03 사진칸이 빈 회색 상자 6개** (3명 · 3~4) | **캡처 아티팩트였다.** 프로덕션에서 그 7장 모두 200 응답·실제 GIF(126~191KB)로 내려온다. `loading="lazy"` + 전체 페이지 캡처 타이밍 문제다. 패널 잘못이 아니라 **우리 캡처 스크립트가 잘못된 증거를 만들었다.** (다만 인쇄·PDF에서 지연 로딩이 빠질 위험은 별도 확인이 필요하다.) |
| **목록·상세 첫 사진이 지적도** (13명 관련 테마) | **부분 사실.** 이 물건은 기일 남은 440대 중 `photo_order`가 없는 **2대** 중 하나였다(0.5%). 다만 `_pick_photo_url`의 폴백이 `map_photos`를 제외하지 않아 **미분류 물건은 구조적으로 지도부터 나온다** — 폴백에서 지도만 빼면 고쳐진다. |
| **홈 신뢰도 76인데 리포트는 81** (2명 · 3) | **서로 다른 물건이다.** 홈 추천 카드의 차와 상세·리포트의 차가 다르다. 같은 차의 불일치가 아니다. |

> 이 표가 이번 회차의 가장 큰 수확이다. 화면만 보는 평가자는 **맞는 것을 틀렸다고 할 수 있고**(산식·사진),
> 동시에 **아무도 안 보던 진짜 결함을 짚는다**(기일 시각·화물 세율·하한에 걸린 예측값).

## 이 리포트의 한계

- 시뮬레이션 패널이다. 인원수는 실제 사용자 비율이 아니라 **몇 종류의 맥락에서 걸리는가**로 읽는다.
- 정지 화면 7장 기준이다. 접힌 것(툴팁 내용·정렬 옵션), 시간 축이 있는 것(로딩·클릭 후 동작),
  계정에 걸린 것(동기화)은 판정할 수 없어 '확인불가'로 뒀다.
- 상세·리포트는 벤츠 S350 승용 **1건**만 봤다. 화물 물건의 상세·리포트에서 취득세가 실제로 어떻게 찍히는지,
  사고 이력이 '확정'인 물건에서 출처 표기가 붙는지는 미검증이다.
- 대표 물건이 `photo_order` 없는 2/440에 해당해 사진 관련 지적이 과대 표집됐다. 다음 회차에는
  캡처 스크립트가 **분류가 끝난 물건**을 고르도록 조건을 넣어야 한다.
- 캡처 스크립트의 지연 로딩 때문에 리포트 사진칸이 빈 상자로 찍혔다. 증거를 만드는 도구가 틀리면
  평가 전체가 흔들린다 — 스크립트를 고쳐야 한다.
