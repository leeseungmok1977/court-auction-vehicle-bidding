# 주간 전문가 패널 리포트

중고차·앱디자인·경매·앱품질 전문가 4인(에이전트)이 매주 라이브 앱을 직접 써보고
100점 루브릭으로 채점한 기록이다. 파일명은 평가일(`YYYY-MM-DD.md`).

- 실행: `/weekly-expert-review` (정의: `.claude/skills/weekly-expert-review/SKILL.md`)
- 에이전트 정의: `.claude/agents/{usedcar-expert,app-design-expert,auction-expert,app-qa-auditor}.md`
- 공통 제약·제품 범위: `.claude/agents/_panel-context.md`
- 스크린샷: `screenshots/weekly/YYYY-MM-DD/`

## 읽는 법
점수 자체보다 **합의 지적**(둘 이상이 같은 문제를 지적한 것)과 **회차 간 증감**을 본다.
지적이 사실인지는 총괄이 코드·라이브·DB로 재검증한 뒤 리포트에 결과를 적는다 — 전문가가 원인을 잘못 짚은 사례가 실제로 있었다.
한 명만 지적한 것은 관점 차이일 수 있지만, 둘 이상이 겹치면 실제 결함일 가능성이 높다.

## 18인 페르소나 패널 (별개 트랙)

전문가 4인이 **직업적 기준**으로 채점한다면, 페르소나 패널은 20~70대 사용자 18인이 **쓰다 막히는 곳**을 찾는다.
기록은 `persona/` 아래에 둔다. 시뮬레이션이라 절대값은 통계가 아니다 — 세그먼트 격차와 반복 테마로 읽는다.

\* 1·2회차는 지시문이 달라(1회차 상한 7점 성향, 2회차 1~10 기준 명시) **점수를 직접 비교하지 않는다.** 비교 근거는 지난 불편 36건의 해소 판정이다.
**화면만 보는 평가는 맞는 것을 틀렸다고도 한다** — 2회차 최대 지적(산식 불일치·리포트 사진 누락)은 재검증에서 각각 '계산은 맞고 표기 문제', '캡처 아티팩트'로 뒤집혔다. 지적은 백로그에 넣기 전에 코드·프로덕션으로 확인한다.
