# 주간 보고서

매주 한 번, 지난 7일을 돌아보는 기록입니다. 파일 이름은 ISO 주차(`YYYY-Www.md`)입니다.
조직 헌장은 [`docs/ORG.md`](../ORG.md), 매일 기록은 [`docs/daily-reports/`](../daily-reports/)에 있습니다.

## 왜 주간이 따로 있나

일일 리포트는 **"어제 작업이 제대로 돌았는가"** 를 봅니다. 주간은 **"제품이 나아지고 있는가"** 를 봅니다.
하루 단위로는 방문자가 28명에서 81명 사이를 오르내려 추세가 안 보이고, 화면을 고친 효과도
하루로는 판단할 수 없습니다.

## 담기는 것

| 구분 | 내용 | 출처 |
|---|---|---|
| **성장** | 방문자·1페이지 이탈·깊이 도달·외부 유입, 지난주 대비 증감 | 운영 접속 로그(읽기 전용) |
| **제품** | 물건 수, 추천 수, 예측 정확도, 시세 커버리지 | 운영 DB(읽기 전용) |
| **품질** | 전문가 패널 4인 점수와 합의 지적 | [`docs/reviews/`](../reviews/) |
| **배포** | 이번 주 커밋과 무엇을 고쳤는지 | git |
| **고객의 소리** | 오너가 넘겨준 스토어 리뷰·이메일 | 오너 입력(없으면 '없음') |

## 읽는 법

- **증감을 본다.** 절대값보다 지난주 대비 방향이 중요합니다.
- **이탈률을 먼저 본다.** 유입을 두 배로 늘려도 첫 화면 이탈이 그대로면 실사용자는 늘지 않습니다
  (2026-09-22 기준선: 1페이지 이탈 **67%**, 외부 유입 하루 **2.8건**).
- **고객의 소리가 0건이어도 행동 데이터는 있습니다.** 말이 없다고 문제가 없는 게 아닙니다.

## 정직 규칙

- **0건 단계를 성공으로 부풀리지 않습니다.** 읽지 못한 곳은 '확인 불가'로 적습니다.
- 표본이 없으면 그 줄을 통째로 숨깁니다 — 빈칸을 추정치로 채우지 않습니다.
- 리뷰 3건을 "고객들이 원한다"고 쓰지 않습니다. **"3명 중 2명"** 이라 쓰고 같은 기간 방문자 수도 함께 적습니다.
- 서버 주소·키 경로는 리포트에 남기지 않습니다(저장소에 커밋되는 문서입니다).

## 만드는 법

```
python tools/weekly_report.py            # 이번 주
python tools/weekly_report.py 2026-09-22 # 그 날짜가 속한 주
```
