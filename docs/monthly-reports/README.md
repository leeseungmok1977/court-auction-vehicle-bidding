# 월간 보고서

한 달을 종합해 **오너가 다음 달 우선순위를 정하는 데 쓰는** 기록입니다.
파일 이름은 `YYYY-MM.md`입니다. 조직 헌장은 [`docs/ORG.md`](../ORG.md)에 있습니다.

## ⚠ 이 보고서가 접속 로그를 직접 읽지 않는 이유

운영 서버의 nginx 로그는 **14일만 보존**됩니다(`rotate 14`, 일 단위). 한 달 전 로그는
이미 지워지고 없습니다. 그래서 월간 성장 지표는 **[일일 리포트](../daily-reports/)에 이미
기록된 `## 방문자` 표를 읽어 누적**합니다 — 일일 리포트는 저장소에 영구 보존되므로
이 방법만이 사실을 말할 수 있습니다.

따라서 **일일 리포트가 빠진 날은 월간에서도 빈칸**입니다. 그 날을 추정으로 메우지 않고
"기록 없음 N일"이라고 적습니다.

## 담기는 것

| 구분 | 내용 | 출처 |
|---|---|---|
| **고객 유입** | 월 방문자·신규·재방문, 이탈률 추세, 유입 경로 구성 | 일일 리포트 누적 |
| **고객가치** | 예측 정확도, 추천 가능 물건 수, 시세 커버리지, 검증 표본 증가 | 운영 DB |
| **고객의 소리** | 한 달간 들어온 리뷰·문의의 갈래별 집계와 조치 결과 | 오너 입력 + 주간 보고서 |
| **품질** | 전문가 패널 점수 추이(월 4~5회차) | `docs/reviews/` |
| **개발** | 커밋 수, 주요 변경, 테스트 수 증감 | git |
| **수익** | 현재 **결제 비활성**이라 '해당 없음'. 활성화는 오너 승인 사항 | `docs/MONETIZATION_SPEC.md` |
| **다음 달 우선순위** | 위 지표에서 도출한 3~5건 | 제품기획 |

## 읽는 법

- **고객가치 지표가 먼저, 수익이 나중입니다.** 순서를 뒤집으면 이 제품이 파는 정직이 무너집니다.
- **한 달은 판단하기에 짧을 수 있습니다.** 표본이 얇으면 "아직 판단 불가"라고 적는 편이
  틀린 결론보다 낫습니다.
- 지표가 나빠졌다면 그대로 적습니다. 나빠진 달을 좋게 쓰면 다음 달 판단이 전부 어긋납니다.

## 만드는 법

```
python tools/monthly_report.py           # 지난달
python tools/monthly_report.py 2026-09   # 특정 월
```
