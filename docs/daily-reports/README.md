# 매일 작업 결과 리포트

매일 12시에 지난 24시간 동안 돈 작업의 결과를 일자별 파일로 남깁니다.
파일 이름은 리포트 날짜(`YYYY-MM-DD.md`)이고, 기간은 **전날 12:00 ~ 당일 12:00(한국 시간)** 입니다.

## 리포트에 담기는 것

| 작업 | 실행 위치 | 일정 | 리포트가 적는 것 |
|---|---|---|---|
| 매일 시세·낙찰 갱신 | 운영 서버 | 매일 06:30 | 단계별 건수(입찰예정·시세 분석·동급 참조·사진 정렬·낙찰결과·무결성 검토·당시 출시가)와 성공·실패. 당시 출시가 수집은 맨 뒤에서 최대 3시간 넘게 돌며, 멈춘 사유(예산 소진·차단·오류)를 함께 적는다 |
| SSL 인증서 갱신 확인 | 운영 서버 | 하루 2회 | 실행 횟수·실패 횟수 |
| 주간 전문가 패널 | 클라우드 루틴 | 매주 토 09:20 | 리포트 커밋 여부 |
| 사진 미분류 점검 | 이 PC | 매주 일 08:17 | 실행 여부·미분류 건수·종료 코드 |
| 집 회선 터널 | 이 PC | 상시 | 작업 상태·엔카 연결 상태·재접속 횟수 |

정기 작업 외에 사람이 직접 돌린 실행(시세 재교정·재분석 등)은 **수동 실행** 표에 따로 적습니다.

## 결과 표기

| 표기 | 뜻 |
|---|---|
| ✅ 성공 | 예정대로 돌았고 실패한 단계가 없음 |
| ⚠️ 경고 | 돌긴 했지만 일부 단계가 실패하거나 확인이 필요함 |
| ❌ 실패 | 실행이 오류로 끝났거나, 예정 시각이 지났는데 실행 기록이 없음 |
| ⏭️ 미실행 | 앞 단계에서 멈춰 이 단계는 돌지 않음 |
| ⏳ 진행 중 | 리포트 시점에 아직 돌고 있음 |
| ❔ 확인 불가 | 기록을 읽지 못함 — **모르는 것을 성공으로 적지 않습니다** |
| — 없음 | 이번 기간에 예정이 없거나 처리할 대상이 0건 |

## 만드는 방법

- 스크립트 `tools/daily_ops_report.py`, 작업 스케줄러 `naechaget-daily-report`(매일 12:00, 로그온 없이 실행).
- 운영 서버·이 PC·GitHub를 **읽기만** 합니다. 법원·엔카 같은 외부 사이트에는 요청하지 않습니다.
- 서버 기록은 0건인 단계를 문장에서 빼므로, 빠진 단계는 '0건 · 없음'으로 적습니다.
- 중간에 끊긴 실행은 마지막 진행 메시지로 어느 단계에서 멈췄는지 판정합니다.
- 당시 출시가 수집이 예산을 다 써서 멈춘 것은 백필을 여러 날에 나눠 도는 정상 동작이라 성공으로, 차단·오류는 실패로 적습니다.
- 출시가 수집 도중 서버가 재시작돼 끊긴 날은 앞 단계 건수가 남아 있으므로 갱신 전체를 실패가 아니라 경고로 적습니다.
- 자동 커밋은 하지 않습니다. 파일만 이 폴더에 쌓입니다.

```
python tools/daily_ops_report.py                  # 오늘 리포트
python tools/daily_ops_report.py --date 2026-09-15
python tools/daily_ops_report.py --stdout         # 파일 대신 화면에
```

