### 재촬영 절차 — 제출 직전 + 월 1회 (오너 승인 2026-09-24 · `PANEL-54`)

**왜 절차인가.** 같은 날 다시 찍은 `02_accuracy.png` 가 **8시간 만에 또 낡았다**(±9.5→±9.6% · 275→288건).
어떤 캡처도 찍는 순간부터 낡는다. 그래서 **시점을 그림 안에 적고**(오버레이), **정기적으로 다시 찍어
갈라진 것만 오너에게 올린다.** 등록정보 문구는 숫자를 빼서 해결했지만(`PANEL-13`), 그림에는 그 처방을 쓸 수 없다.

**언제** ① 콘솔에 자산을 올리기 **직전, 같은 날** ② **매월 1일**(월간 리포트와 같은 날)
③ 화면 어휘·판정 표기를 바꾼 배포 직후 — `report.html`·`detail.html`·`accuracy.html`·`landing.html`·
`dashboard.html`·`calendar.html` 을 건드린 커밋이 배포됐을 때.

**순서**
1. `python tools/capture_store_shots.py --all` — 8장을 다시 찍는다. 도구가 규격·중복·기대 라벨·
   폐기 어휘(`RETIRED`)·관리자 UI 누수를 스스로 검사하고, **걸리면 파일을 남기지 않는다.**
2. `python tools/capture_store_shots.py --audit` — 8장 전부 md5·규격·기준 커밋(`HEAD.json`)을 대조한다.
   종료코드 1 이면 제출하지 않는다. **일부만 보는 대조는 대조가 아니다.**
3. 전/후 md5 가 바뀐 장을 **Read 로 직접 열어** 본다 — ① 번호판이 읽히는가(가리지 않는다 — 알고만 있는다)
   ② 없는 기능을 광고하는 표시가 섞였는가 ③ 파일명과 실제 화면이 같은가.
4. 오버레이를 얹는다(`tools/store_overlay.py` — 시안 확정 후 도구에 통합 예정). 기준 월을 촬영 월로 갱신한다.
5. **바뀐 장만** 오너에게 올린다 — 무엇이 왜 달라졌는지(어휘/수치/기일/물건) 한 줄씩. **자산 교체는 오너 권한이다.**

**하지 않는 것** 콘솔 업로드 자동화(오너 권한) · 캡션 문구 변경(오너 확정본) · 대상 물건의 무작위 교체
(캡션 조건을 만족하는 물건이어야 한다 — `pick_hero_vehicle()` 이 거른다).

⚠ **선결 과제**(지시서 2026-09-24-03 진행 중): `pick_hero_vehicle()` 의 후보 조사가 프로세스 안에만 캐시돼
