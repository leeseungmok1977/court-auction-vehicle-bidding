# 준법·리스크 검토 (compliance-officer)

> 코드가 아닌 리스크 검토·로드맵. **최종 법적 판단은 사람(변호사)에게 위임.** 여기서 "합법"을 단정하지 않는다.
> billing 활성화·유료 시세 노출은 아래 완화방안 충족 전까지 **불가**.

## 2. 대체 시세 소스 로드맵 (엔카 의존 탈피)
1. **(a) 자체 축적 낙찰가 DB** — 우리가 합법적으로 모은 실제 낙찰가로 예측(백테스트 기반). **가장 안전**, 데이터 축적할수록 정확. → 우선 투자.
2. **(b) 공식 제휴/공개 API** — 엔카·케이카·KB차차차 제휴 또는 공개 시세 API 조사.
3. **(c) 공공데이터** — 국토부 자동차 이전등록/자동차관리정보 등 활용 가능성 조사.

## 3. 개인정보(회원 DB) 체크리스트
- [ ] 최소수집(이메일 등), 수집·이용 동의, 목적 명시
- [ ] 비밀번호 해시(bcrypt 등)·전송 암호화(HTTPS)
- [ ] 보관기간·파기 정책, 접근통제
- [ ] 개인정보처리방침 게시

## 4. 전자상거래 표시의무 체크리스트
- [ ] 사업자정보(상호·대표·사업자번호·주소·연락처)
- [ ] 이용약관·개인정보처리방침·환불규정
- [ ] 결제 전 과금 조건 고지, 청약철회 안내

## 5. 결론(현재)
- **감정평가서 원본 연결(뷰어)**: 저장·재배포 없이 공식 원본을 여는 현 방식은 리스크 낮음 → 진행 가능.
- **엔카/케이카 시세의 유료 노출**: §2 대체 소스 전환 또는 제휴 확인 전까지 **보류**. 무료 검증 도구로는 현 방식 유지 가능(사용자 승인 하).
- **개인 식별정보**: 유료화 전 마스킹·최소화 검토.
- 결제·회원 활성화: §3·§4 충족 + 위 시세 이슈 해소 후, 사람(변호사) 최종 확인 하에.
- **보배드림 신차가격표**: §6 참조 — **조건부 가능**(내부 파생값 한정). 유료 리포트에 출처와 함께 노출하는 것은 §6.7 조건 (A) 또는 (B) 충족 전 **불가**.

## 6. 보배드림 '신차가격표' 활용 검토 (2026-09-11 추가)

> 이 절도 §1~§5와 동일하게 **리스크 식별·로드맵**이며 법적 판단이 아니다. 인용한 조문·판례 번호는 검토자 기억에 근거하므로 **변호사가 원문으로 재확인**한다.

- 수집: 서버가 물건의 제조사·모델·연식에 맞는 페이지만 소량·저속으로 읽음. 요청 간 5초, 모델당 약 30요청, 일일 상한 300, 모델 단위 1회 캐시.

### 6.2 엔카 사례와의 일관성 판단

| 비교 항목 | SK엔카(기존 결론) | 보배드림 신차가격표(제안) |
|---|---|---|
| robots.txt | 전면 `Disallow: /` | 없음(404) — **엔카보다 유리** |
| 약관상 금지 | (검토 당시 미상) | **영리행위·정보 복제·타인 제공 명시 금지** — 엔카와 실질 동등한 거부 의사 |
| 데이터 성격 | 매물 시세(보배드림 대비 변동성 큼, 원자료 자체가 상품) | 제조사 공표 사실(출시가)의 편집·DB — 원 사실은 공공연히 알려진 정보 |
| 우리 저장물 | 중앙값·표본수·분포(원자료 통계) | min/max/등급수/출시일 구간 |
| 공개 노출 | **관리자 전용, 공개 화면 비노출**(M01) | **유료 리포트에 출처와 함께 노출 예정** — **엔카보다 노출 수위가 높음** |
| 실제 차단 | 2026-09 서버 IP 차단됨 | 없음(아직) |

결론: 저작권 관점은 보배드림이 엔카보다 안전하지만, 약관 금지가 명시적이고 노출 수위는 더 높다. **일관성을 지키려면 초기에는 엔카와 같은 격리 원칙(파생값 계산에만 사용, '보배드림' 문자열과 범위 자체는 관리자 화면 한정)을 적용하고, 공개·유료 노출은 6.7 조건 충족 후 열어야 한다.** 단, 이용하는 이상 출처 표기는 옳다 — 숨기고 쓰는 것보다 밝히고 쓰는 편이 '공정한 관행' 판단에 유리하다. 문제는 표기 여부가 아니라 **허락 없는 공개 재제공** 자체다.

### 6.3 저작권·DB권 관점 정리 (검토 항목 1)

- **사실 정보**: 가격·등급명·출시일은 저작물이 아니다. 보배드림이 이 사실의 원천(제조사)도 아니다. → 개별 사실 인용 자체의 저작권 리스크는 **낮음**.
- **편집물**: 보호 대상은 선택·배열의 창작성뿐이며, 우리는 배열을 복제하지 않는다. → **낮음~중간**(창작성 인정 여부는 다툼 여지, 단정 불가).
- **데이터베이스제작자 권리**: 가장 실질적인 쟁점. '상당한 부분' 기준은 **양적(전체 대비 비율)과 질적(투자의 핵심 부분인가)** 모두로 판단하며, 여기에 **제93조 제2항의 반복적·체계적 추출 간주 조항**이 붙는다. 모델당 집계값은 양적으로 미미하나, 시스템이 물건마다 모델을 순회하고 캐시가 누적되면 "반복적·체계적"이라는 문언에 걸린다. 우리 쪽 방어는 (i) 저장물이 소재의 복제가 아닌 2차 통계라는 점, (ii) 누적 범위가 물건 발생에 따른 필요 한도라는 점, (iii) 통상적 이용(사용자가 가격표를 열람하는 것)과 충돌하지 않고 오히려 링크로 환원한다는 점. **이 방어가 통하는지는 변호사 판단 사항이며, 이 검토는 "낮다고 볼 여지가 있다"까지만 말한다.**
- **공정이용(제35조의5)**: 비영리가 아니고 유료 리포트에 쓰므로 목적 요소는 불리, 이용 분량은 유리, 시장 대체성은 낮음. 보조 근거로만 활용.

### 6.5 리스크를 낮추는 운용 조건 (검토 항목 2 — 체크리스트)

**요청 통제**
- [ ] 요청 간 5초 이상, 동시 연결 1, 재시도 최대 2회·간격 30초(C.4 그대로).
- [ ] 모델당 30요청 이하, 일일 300요청 이하를 **코드 하드캡**으로 강제(설정으로 늘릴 수 없게).
- [ ] 트리거는 **물건 발생 시 on-demand**만. 전체 제조사·모델 카탈로그를 선제 순회하는 배치 금지.
- [ ] 캐시는 모델·연식 단위 **영구 1회**(출시가 불변). 재수집은 신규 연식이 등장했을 때만.
- [ ] 누적 커버리지 상한(예: 모델 500개). 도달 시 자동 정지 + 재검토.
- [ ] User-Agent에 서비스명·연락 이메일 기재. 브라우저 위장·프록시·IP 변경 금지.
- [ ] 회원 로그인·쿠키·세션 미사용.
- [ ] 피크 시간대(예: 09~18시) 회피, 야간 저속 실행.

**저장·표시**
- [ ] 저장 필드: 출시가 min·max, 등급 수, 출시일 구간, 수집일, 조회 URL. **등급명·개별 가격·HTML·이미지·문구는 저장 금지(로그 포함).**
- [ ] 표시 문구(초안): "출시가 범위(참고): 3,294~4,5xx만원 · 등급 n개 · 출처: 보배드림 신차가격표(YYYY-MM 조회) · 본 서비스는 보배드림과 제휴관계가 없으며, 위 수치는 참고용이고 정확성을 보증하지 않습니다." + 해당 가격표 페이지 링크(트래픽 환원).

- [ ] 매칭 신뢰도 낮은 물건은 미표시(R9).

**중단·옵트아웃**
- [ ] 자동 중단 조건: 403/429/407, CAPTCHA, 비정상 응답 3회 연속, robots.txt에 `Disallow` 등장, 약관 개정으로 자동수집 명시 금지.

**기록**

- **localStorage(favs·notes·large·scroll·splash)**: Google 기준은 *"'Collect' means transmitting data from your app **off a user's device**"*이고 면제 (a)가 **기기를 떠나지 않는 데이터**다(2026-09-22 확인, `reports/2026-09-22-compliance-출시전-신고정합성.md` G2·G3). 기기를 떠나지 않으므로 **수집 아님**. 신고 영향 없음.
- **쿠키 `last_list`**: localStorage와 달리 **매 요청 서버로 전송된다.** 그럼에도 수집으로 보기 어렵다고 판단하는 근거는 셋이다 — ① 내용이 *우리가 방금 내려준 우리 자신의 목록 URL*이고 ② 서버는 '이전 목록' 링크를 만드는 데만 쓰고 저장하지 않으며(`app.py:761-763`, 내부 상대경로만 허용) ③ 난수 ID·세션 ID 같은 **식별자가 아니다**(Google의 'Device or other IDs' 예시는 IMEI·MAC·Widevine·Firebase ID·광고 ID). **이것은 해석이며 단정이 아니다.**
  ⚠ **뒤집히는 조건**: 이 쿠키에 임의 ID(세션·방문자 식별자)를 넣는 순간 '기기 또는 기타 ID' 판정으로 넘어간다. 쿠키에 식별자를 추가하는 변경은 **오너 승인 사항**(ORG §3)으로 취급해야 한다.

### 8.3 항목 3 — `/terms` 404: 출시 시점에 이용약관이 없어도 되는가

**판단(법적 단정 아님)**

- **Play 심사**: 필수는 **개인정보처리방침**이다. 이용약관은 **UGC를 만들거나 업로드하는 앱**에서 수락 절차를 요구하는 맥락으로 서술된다([앱 준비](https://support.google.com/googleplay/android-developer/answer/9859455?hl=ko), [개발자 정책](https://support.google.com/googleplay/android-developer/answer/14906471?hl=ko)). 이 앱은 댓글·게시판·업로드가 없다(콘텐츠 등급 답안 §3과 일치). → **Play 관점에서 출시 차단 요인 아님.**
- **전자상거래법 제10조**(사이버몰 운영자 표시의무: 상호·대표자 성명·주소·전화·이메일·사업자등록번호·**이용약관**·호스팅사업자 상호를 초기화면에 표시)는 *"전자상거래를 하는 사이버몰의 운영자"*에 걸린다([조문 해설](https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=25&ccfNo=3&cciNo=1&cnpClsNo=1)). 현재는 **판매·결제·광고가 전혀 없어** 적용 대상으로 보기 어렵다는 것이 이 검토의 잠정 판단이다. **유료 전환 시에는 §4 체크리스트 전부가 한꺼번에 걸린다.**
- **실질적 손해**: 약관이 없으면 ① 서비스 이용조건·면책 ② **§6.5/§6.6의 데이터 제공 중단(권리자 요청 시)** ③ 분쟁해결·준거법을 계약으로 못 박을 자리가 없다. 특히 ②는 유료 이용자에게 사전 고지해 둬야 환불 분쟁을 예방하는 항목이다(§6.6-4).

**판정: 출시 차단 아님. 출시 후 정비 1순위.** 심각도 **중간**(무료 v1) → **높음**(유료 전환 시).

**왜 문제인가**
- 2026-09-22 보고서 5-1이 정확히 이 항목을 "출시 신청 직전 대조하라"고 예고했고, **실제로 어긋났다.** 검증 표본이 매일 쌓이므로 **기준 시점 없이 숫자만 박으면 반드시 낡는다.**
- Play는 등록정보·스크린샷 등 모든 메타데이터가 앱을 정확히 반영할 것을 요구하고, 허위표시를 삭제·정지 사유로 든다([Misrepresentation](https://support.google.com/googleplay/android-developer/answer/9888689), [개발자 정책](https://support.google.com/googleplay/android-developer/answer/14906471?hl=ko)).

**심각도: 중간. 출시 전 처리 권고.**
완화: 출시 신청 직전 라이브 값으로 교체하고 **"2026년 9월 기준"처럼 기준 시점을 병기**한다. 등록정보 텍스트는 콘솔에서 즉시 수정되며 재빌드가 필요 없다.
**미확인**: Play Console에 **실제로 저장돼 있는** 문구. 나는 콘솔을 보지 못했고 저장소 문서와 대조한 것이다. 콘솔 값이 이미 갱신돼 있으면 이 항목은 자동 해소된다.

**함께 발견(낮음)**: `STORE_LISTING.md:63` "가입·로그인·결제·광고 없이 바로 이용합니다. **개인정보를 수집하지 않습니다.**" 는 `/privacy` §1이 접속 로그·쿠키를 수집 항목으로 적어 둔 것과 **문자 그대로는 충돌한다.** Play 신고 기준으로는 '수집 없음'이 성립하지만(8.1), 이용자에게는 두 문장이 서로 다른 말로 읽힌다. 완화: "개인정보를 수집하지 않습니다(계정·결제·광고 없음 — 서버 운영 로그만 일정 기간 보관)"처럼 한정하면 양쪽이 같은 말이 된다.

### 10.2 공통 원칙 초안 (조사 에이전트 운용 규칙)

**요청 통제**
- [ ] 소스당 **1일 20건**(글 1건 + 그 댓글 = 1건), 요청 간 **10초**, 동시 연결 1, **런당 총 요청 60 하드캡**, 주간 소스당 100건 상한. 코드 하드캡(설정으로 못 늘리게)은 §6.5와 동일 원칙.
- [ ] **검색 엔드포인트 미사용** — 클리앙(`/service/search*`)·블라인드(`/search/`)·뽐뿌(`/search_bbs.php`)·티스토리(`/search`) 전부 robots 금지. 목록 1페이지 → 글 본문 순서만.

- [ ] 런 시작마다 robots.txt 재확인. `Disallow` 확장·우리 UA 추가 시 **그 소스 자동 중단**.
- [ ] 403/429/CAPTCHA/차단 → 즉시 중단 + **그 소스 영구 제외**(운영자 의사표시로 간주, §6.5). IP 변경·UA 위장·프록시 **금지**.
- [ ] 로그인·쿠키·회원 세션 미사용. 야간 저속 실행.
- [ ] UA에 서비스명·연락 이메일 기재(도구가 허용하는 범위에서 — G6 실측 후 결정).

**저장 금지 항목(로그 포함)**
- 원문(문장 단위·따옴표 인용 포함), HTML, 이미지, 댓글 트리 구조
- 닉네임·ID·프로필·**회사명(블라인드)**·직군·연차
- 게시글 URL·게시글 번호·작성일시(분 단위)
- 요약 안의 식별 요소: 실명·사건번호·차량번호·**지역+차종 조합**·**금액+날짜 조합**·물건 주소·직장

**저장 허용(설계 그대로)**: 소스명, 수집일(일 단위), 범주, 단계, 감정 강도(척도값), 30자 요약, 미충족 니즈(코드값).
- 30자 요약은 **원문과 5어절 이상 연속 일치 시 재작성**(표현 복제 방지 검사). 짧은 댓글은 요약이 원문과 같아지기 쉽다 — 그 경우 자유 텍스트를 비우고 코드값만 남긴다.
- 중복 제거용으로 URL 대신 **솔트 해시**를 남길지는 오너 결정(D3). 해시가 있으면 삭제 요청에 대응할 수 있고, 없으면 출처 추적이 불가능하다.

**보관 기간**
- 분류 결과 행: **180일**. 주간 인사이트 리포트가 확정되면 집계표(범주별 건수·비율)만 남기고 행을 삭제할 수 있다.
- 원문·HTML·중간 산출물: **0일**(메모리 처리 후 폐기). 로그에는 소스·건수·요청 수·중단 사유만.

**skip 규칙(최소)**: ① 광고·홍보·업체 후기·강의 모집 ② 판매·중고거래 글(클리앙 `sold`는 robots도 금지) ③ 특정 물건(사건번호·주소)을 다루는 글 ④ 도배·중복 ⑤ 신문기사 전재.

**결과물의 공개 범위**
- **내부 리포트(`reports/`)만.** 랜딩·스토어 등록정보·블로그·SNS에 "커뮤니티 조사 결과 n%"·소스명·인용 **금지** — 특히 블라인드·태인 이름은 어떤 외부 문구에도 넣지 않는다.
- 제품 개선(문구·FAQ·기능 우선순위)에 반영하는 것은 가능하되 출처 표기 없이. 외부에 수치를 쓰면 표시광고법 실증 대상이 된다(§8.7 논리).

**옵트아웃·기록**
- 소스 운영자 서면 요청 수령 시 **24시간 내** 해당 소스 제외 + 그 소스 행 삭제(§6.5와 동일 기준). 창구는 방침 §8 이메일.
- 런별 요청 수·소스·중단 이력, robots 확인 결과를 남긴다(원본 데이터 없이 카운트만).

### 10.3 블라인드 판정 — 본문 요약만 저장해도 되는가, 회사명은 지워야 하는가

**결론: 자동 수집 대상에서 제외한다(높음).** 근거 셋:
1. **약관 제3조가 "자동/수동 수단을 통한 크롤링·스크래핑·데이터 마이닝·데이터 추출"을 명시적 허가 없이 금지**한다. "요약만 저장"은 저작권 방어(표현 미복제)에는 유효하지만, 약관이 금지하는 것은 복제가 아니라 **추출 행위 자체**라 이 방어가 닿지 않는다. 소량·수동이라는 반론도 "자동/수동" 문언에 막힌다.
2. robots가 **`ClaudeBot`·`anthropic-ai`를 전면 차단**한다. 우리 도구 UA가 무엇이든 Anthropic 계열 자동 접근을 거부하는 의사가 명문이다(G6).
3. **익명 직장인 커뮤니티 + 회사명 표시 구조.** 블라인드 약관 제2.2조가 게시자에게 결합 식별 정보 게시를 자제하라고 요구하는 것은, 회사명이 이미 붙어 있는 상태에서 **내용 몇 가지만 더해지면 유추 가능**하다는 뜻이다. 개인정보 보호법 제2조 제1호 나목(다른 정보와 쉽게 결합하여 알아볼 수 있는 정보)의 전형적 사례로 다퉈질 수 있다.

**회사명은 지워야 한다** — 결론은 포함 여부와 무관하게 같다.
- 우리 목적(경매 참여자의 심리·니즈)에 회사명은 **불필요**하다 → 최소수집(개인정보 보호법 제3조 제1항·제16조 제1항) 위반 소지를 스스로 만들 이유가 없다.
- 회사명을 "대기업 직장인"·"공기업"처럼 일반화한 표현도 요약에 넣지 않는다 — 직군·연차·지역과 결합하면 다시 좁혀진다.

**오너가 그래도 포함하기로 결정한다면 최소 조건(전부 충족, 그래도 등급은 중간 이상)**
- [ ] Teamblind에 서면 허락 문의 발송·기록(약관 제3조 "명시적 허가" 요건). 회신 없음은 허락이 아니다.
- [ ] 회사명·직군·연차·지역·성별 전부 제거. 글 단위 행을 만들지 않고 **주제 단위 집계값만** 저장.
- [ ] 1일 5건 이하, 검색 미사용, 로그인 미사용.
- [ ] G6 UA 실측 결과 Anthropic 계열이면 즉시 제외.
- [ ] 변호사 의견(약관의 비회원 구속력 + 데이터 추출 금지 조항의 효력 범위).

### 10.4 유튜브 Data API — 댓글 텍스트 저장·요약의 허용 범위 (공식 문서 기준)

**확인된 문서(2026-09-26 직접 조회)**
- `www.youtube.com/robots.txt`: `User-agent: *`에 `/api/`, `/login`, `/signup`, `/watch_ajax`, `/youtubei/` 등 다수 경로 Disallow → **API 밖 스크래핑은 robots로 거부**, Data API가 유일한 정당 경로.
- **YouTube API Services Terms of Service**: §3.1 "the means described in the Agreement, including in accordance with the documentation"로만 접근; §5 개인정보 관련 법령 준수; **§7** "Each API Client will provide and adhere to a published privacy policy that clearly and accurately describes to its users what user information you and your API Client access, collect and store"; §10.3 Branding Guidelines에 따른 출처 표시; §11 저작자 표시(author attributions) 삭제·위조 금지; §24.3 종료 시 "delete all YouTube API Services (including all API Data)".
- **YouTube API Services Developer Policies (Last updated 2026-09-14)**:
  - 정의: "**Non-Authorized Data** means API Data accessible by an API Client without User Credentials" — 공개 댓글이 여기 해당.
  - **III.E.4.d**: "API Clients may temporarily store limited amounts of Non-Authorized Data … but not longer than 30 calendar days."
  - **III.E.4.h**: "API Clients must not (i) replace API Data with similar, independently calculated data, or (ii) **access or use API Data to create new or derived data or metrics**."
  - **III.E.2.a**: "**Do not aggregate API Data** except that you may only aggregate API Data relating to YouTube channels that are under the same content owner …"
  - **III.F.2.a**: YouTube 콘텐츠를 표시하는 페이지·기능은 YouTube가 출처임을 Brand Features로 명시; **III.F.2.c**: YouTube가 제공하는 attribution을 "interfere with or obscure" 금지.
  - 댓글을 특정한 조항: III.F.3.c(댓글 작성 등 참여 행위에 대한 보상 제공 금지) 정도이며, **댓글 텍스트의 분석·감정 분류를 직접 허용하거나 금지하는 문장은 없다**.

**우리 설계와의 대조**

| 설계 요소 | 충돌 가능 조항 | 심각도 | 판단 |
|---|---|---|---|
| 범주·단계·감정 강도 산출 | III.E.4.h "create new or derived data or metrics" | **중간~높음** | 문언상 댓글에서 만든 감정 강도는 '파생 데이터'다. 조항의 맥락(조회수 등 YouTube 지표를 흉내내거나 대체하는 것을 막는 취지)으로 좁게 읽을 여지는 있으나 **단정 불가** |

**판정: 보류(중간~높음).** 접근 경로 자체는 클리앙·블라인드보다 깨끗하지만, **파생 데이터·집계 금지 조항이 우리 산출물의 본질(분류·집계)과 정면으로 겹친다.** 열려면 ① Google 정책 문의 또는 변호사 의견으로 III.E.4.h·III.E.2.a 적용 범위 확인 ② 30일 후 삭제(집계표만 잔존) ③ 댓글 원문·채널ID·댓글ID 미저장 ④ `/privacy` 갱신 ⑤ 리포트 출처 표기. **API 키 발급·쿼터 신청은 이 조건 확인 전에는 하지 않는다**(외부 계약 성격 — 오너 승인 사항).

### 10.8 한계와 위임

- **UA 실측(G6)을 이 세션에서는 하지 못했다** — 셸·서버 로그 접근이 없다. Steward 또는 오너가 1회 실행하면 클리앙·블라인드 판정이 확정된다.
- 클리앙·뽐뿌·티스토리 **약관 본문 미확인**, 네이버 **전부 미확인**, 태인 `www1.` robots 미확인. 미확인 소스는 "조건부 가능"이지 "가능"이 아니다.
- Google·Anthropic 문서는 예고 없이 개정된다 — 유튜브를 여는 시점에 Developer Policies(Last updated 2026-09-14)를 다시 연다.
- 인용 조문·판례(2014다235080, 2021도1533, 2016다276467, 저작권법 제28조·제35조의5·제93조, 개인정보 보호법 제2조·제3조·제16조)는 **변호사가 원문으로 재확인**한다.
- **법 해석은 전부 변호사에게 위임한다.** 이 절은 각 소스의 robots·약관 문언을 그대로 옮기고 우리 설계와 대조해 리스크를 드러낼 뿐, 어느 소스도 "합법"이라고 단정하지 않는다.

**변경 이력**: 2026-09-26 §10 최초 작성(지시 2026-09-26-03). robots 실측 5+1건, 약관·정책 본문 3건 확보. 제외 권고 3소스(블라인드·태인·네이버), 보류 1(유튜브), 조건부 3(클리앙·뽐뿌·블로그).

## §11 테스터 설문·인터뷰의 동의·보관 (2026-09-26, compliance-officer 판정 — Steward 옮김)

- **Play '데이터 안전' 신고와의 정합**: 수집 정의는 "앱에서 기기 밖으로 전송되는 데이터"(§8 G2). 앱을 거치지 않는 카카오톡 1:1 설문은 신고 범위 밖 → '수집된 데이터 없음' 신고와 충돌하지 않는다. **조건 셋**: ① 설문을 앱 화면·앱 내 링크·스토어 등록정보에서 연결하지 않는다 ② 답변·요지·라벨 행을 서버 경로나 운영 DB 에 두지 않는다 ③ `/privacy` 를 이 설문 때문에 고치지 않는다.
- **동의 고지 4항목**(법 제15조 제2항): 목적·항목·**보유기간**·거부권. 초안에 보유기간이 없었다(높음) → 발송 문구에 "6개월 안에 지웁니다" 명시. 용도는 "앱 개선 + 프로덕션 액세스 신청서의 성함 없는 요지 인용"까지로 한정하고 스토어·랜딩·SNS·마케팅 인용 금지(§10.2 준용).
- **'익명'이라 쓰지 않는다**: 1:1 대화라 오너가 재식별 가능 → **가명 라벨(T1~T12)·성함 미기재**로 표기하고 요지는 개인정보(가명처리)로 취급.
- **처리 순서**: 오너가 성함·프로필·시각·결합 식별 요소(직업·거주지·가족·금액·차량번호·사건번호)를 지우고 라벨을 붙인 뒤 voice 에 넘긴다(AI 는 실명을 받지 않는다). 라벨↔실명 매핑은 오너가 저장소 밖 1곳에 180일 보관(삭제 요청 이행용).
- **보관**: 원문 0일 · 라벨 행 180일(`delete_by`) · 집계표만 잔존. git 커밋본(`reports/`)에는 집계·코드값·주제 서술만 — git 이력은 지울 수 없어 요지 자유문·라벨 행을 넣지 않는다.
- **민감정보·미성년**: 질문 자체엔 없음. 요지에 건강·정치·종교 등 제23조 정보와 금액·가족·직업·거주지·차량/사건번호를 넣지 않는다. **만 14세 미만 수신자에게는 발송하지 않는다**(법정대리인 동의 경로를 만들지 않음, `/privacy` §6 과 일치). 14~19세는 제외 권고(선택).
- **2차 인터뷰**: 녹음하지 않고 메모만(녹음 시 별도 고지·동의 재검토).
- **한계·위임**: 콘솔·라이브·실제 수신자 명단은 보지 않았다. '답장 = 동의' 구조의 유효성, AI 처리의 위탁/국외이전 해당 여부, 방침 제30조 기재 필요 여부는 **변호사 확인**. 합법을 단정하지 않는다.
