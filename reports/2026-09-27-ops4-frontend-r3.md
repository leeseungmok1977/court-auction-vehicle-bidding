## 2. `schedState` — 순서와 이유(주석과 같은 내용)

**지시문과 다르게 읽은 곳 두 가지** — 둘 다 한 줄로 되돌릴 수 있고, 테스트에 변이로 걸어 두었다.

1. **ⓑ 에서 `silence.bad` 를 주황으로 남겼다.**
   - 지시문은 "원자료로 확실한 사실만 빨강으로 두고 **나머지는 '확인 불가'**"다. 나는 '나머지'를 초록·대기·실행 중으로 읽었다.
   - 이유: `silence.bad` 는 순환계가 이미 경보로 판정한 것이다. 이를 회색으로 내리면 결재함은 주황인데 표는 회색이 된다 — 이번 회차가 없애려는 모양의 반대편이다.
   - 서버 `sched_silent` 도 이 행을 세므로 타일은 주황이 된다. 표만 회색이면 타일과 표도 어긋난다.
   - 문자 그대로 읽은 변이(`verdict null 이면 silence.bad 도 확인 불가`)는 테스트 `test_unknown_verdict_only_raw_facts_are_red_and_nothing_is_green` 이 빨갛게 잡는다. Steward 가 문자 그대로를 원하면 그 한 줄과 테스트 기대값을 바꾼다.
2. **ⓐ④ 를 ⓐ⑤ 앞에 두었다**(silence 를 모르면 '아직 때가 안 됨'도 확인 불가).
   - r2 에서는 대기가 주황이라 모름을 가볍게 칠할 일이 없었다. 이번에 대기를 무채색으로 내리면서 생긴 틈을 막은 것이다.
   - 오늘 실제 행에서는 해당이 없다 — 대기 2개 모두 silence 가 판정돼 있다.

**꺼짐 + 실패 행**(backend §7-1 이 frontend 에 맡긴 결정): 칩과 부제 모두 결재함 글자 '꺼짐(Disabled)'로 적는다.
- 서버 수로는 `sched_bad` 에 들어가지만, 타일 부제가 서버 문구가 아니라 **칩 글자**로 세므로 결재함·표·타일 셋이 같은 말을 한다.
- 빨강 합(never + bad + stopped)은 칩 수와 같다(테스트).
- `verdict` 가 null 이면 이 행은 '꺼짐'을 모르므로 원자료대로 '실패'다(테스트).

## 3. 타일 — `schedTile`

- **부제**: 칩 글자별 수. 빨강 → 주황 → '확인 불가' 순이다. 예: `1개 실패 · 1개 꺼짐(Disabled) · 1개 다음 실행 없음 · 1개 첫 실행 없음 · 2개 조용히 안 돎 · 1개 확인 불가`.
  - 볼 것이 없으면 `N개 아직 때가 안 됨`(표 무채색 칩과 같은 글자) 또는 `정상`이다.
  - ⚠ 옛 문구 'N개는 첫 실행 대기(예정일 있음)'를 표 칩 글자로 바꿨다. 지시 4 "타일 글자는 표 칩 글자와 같은 어휘"를 대기에도 적용한 것이다. `heartbeatTile` 의 '첫 매시 스캔 … 예정'은 다른 타일이라 두었다.
  - '실행된 적 없음 · 예정도 없음'은 이제 칩이 '실행된 적 없음' + 아래 '예정도 없음'이다. 그래서 타일도 'N개 실행된 적 없음'이다. 이 상태는 오늘 실제 행에 없다.
- **색**(서버 수):
  - `sched_never`·`sched_bad`·**`sched_stopped`** > 0 → 빨강
  - 아니고 `sched_silent` > 0 → 주황
  - 아니고 칩 '확인 불가'가 있거나 `sched_silent`·`sched_stopped` 가 null → mute
  - 모두 아니면 무채색
- 항목마다 nowrap 은 그대로다.

## 4. 사유 줄 — `schedWhy`(design r2 #3)

- **모양**: `<span class="seg">마지막 성공 <span class="nw">09-25 15:59 ·</span></span> <span class="seg">매일 작업 한도 36시간 넘김</span>` — 줄은 조각 사이 공백에서만 갈린다.
- **1판(U+00A0)이 모자랐던 증거**: `screenshots/ops4-r3/attempt1-nbsp/`, measure JSON.
  - 320·360px 에서 time-split 2 — '09- / 25 17:57', Chromium 이 하이픈 뒤에서 끊었다.
  - 390px 에서 홀로 선 '·' 1 — 터널의 긴 결과 토큰이 칸보다 넓어 `overflow-wrap:anywhere` 가 '·' 바로 앞에서 끊었다.
  - 원인: 3회차에서 빨강 칩이 '실패' 두 글자가 되자, 상태 칸이 320px 에서 163 → 131px 로 좁아졌다(r2 에서는 긴 빨강 칩이 칸을 잡아 줘서 mixed 데이터에서 안 생겼다 — design r2 §#3 관찰과 같다).
- **2판(nowrap 덩이)**: 'MM-DD HH:MM'을 `.nw` 로, 조각 꼬리(끝 글자, 끝이 시각이면 그 시각 + ' ·')를 `.nw` 로 묶었다.
  - 320px 캡처를 눈으로 보니 '3221225477(0xC00000 / 05) ·' — 숫자 **중간**이 갈렸다. `attempt2-nowrap/` 에 있다. 측정 계수에는 이 항목이 없어 **눈으로 잡았다**.
- **최종**: 숫자 바로 뒤 '(' 앞에 `<wbr>` 을 넣었다. 이제 '3221225477 / (0xC0000005) ·'로 갈린다. 측정에 '숫자 갈림' 계수를 더했다.
  - 이 계수가 공허하지 않은지도 확인했다. `<wbr>` 을 뺀 변이를 라우트로 서빙하면 320px 에서 1 이고, 현재는 0 이다.
- **글자 불변**: U+00A0·U+2011 을 쓰지 않았다. 그래서 화면 글자(textContent)가 사유·결재함 라벨과 **글자까지 같다**(테스트).
  - 지시문의 '줄바꿈 없는 공백'과 방법이 다르다. 목적(시각을 한 덩이로)은 같고, 공백만으로는 Chromium 에서 목적을 못 이뤘다(위 증거).
