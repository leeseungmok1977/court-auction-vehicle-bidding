## ③ 고칠 것 — 우선순위순 3건

### #1 결재함 목적 줄이 140자에서 잘려 시각이 `17:5` 로 끊긴다 — backend, 새로 드러남

**화면·요소:** 사내 대시보드 결재함 표 '무엇을' 칸(`td.pp`)의 예약 작업 경보 행

**현재** — 캡처·측정·코드로 확인했다.
- after-inbox-1440·320, after-quiet-inbox-1440·320 모두 weekly 행이 "… · 다음 실행 2026-10-02 17:5" 로 끝난다.
  - measure JSON `pp` 도 같다. CSS 로 잘린 것이 아니라 **글자가 없다.**
- 원인은 `Org` 결재함 목록의 `open_list.append` 에 있는 `"purpose": (purpose[0] if purpose else "")[:140]` 이다.
  - `**`·백틱 6자까지 세서 자른다. weekly 목적 줄은 보이는 글자 134자 + 6 = 정확히 140자에서 끊긴다(내 계산).
  - 같은 이유로 조용한 누락 3행 모두 닫는 괄호 `)` 가 없다. 온전한 것은 터널 행 하나다.
- 1회차에는 없던 일이다.
  - 1회차 목적 줄은 터널 행뿐이었고 끝까지 보였다.
  - backend r2 의 silence 라벨('조용히 안 돎 · 마지막 성공 … · 매일 작업 한도 36시간 넘김')이 앞에 붙으면서 길어졌다.
- 같은 문장의 다른 흠(이미 알려졌고, 여전히 있다)
  - "마지막 성공 09-25 15:53" 과 "(마지막 실행 2026-09-25 15:53" 이 같은 시각을 두 번 말한다.
  - 터널 행은 "다음 실행 없음"을 두 번 말한다(1회차 메모 1, 그대로).
  - 첫 실행 없음 행에 "마지막 실행 1999-11-30 00:00" 이 보인다(frontend §6-3). 표는 같은 경우 '—'로 그린다.
  - "1149시간째"는 주어가 없다. 첫 실행 없음 행에서는 등록 뒤 시간인데, 괄호 안의 1999 날짜와 맞지 않는다.

**목표**
- 목적 줄 첫 줄은 silence 라벨을 **그대로** 앞에 둔다. 표 칩 + 사유와 글자가 같아야 한다 — frontend 테스트가 지키는 것이다. 그 뒤에는 라벨에 없는 것만 붙인다.
  - 조용히 안 돎: `예약 작업 {name} — {label} · 다음 실행 {next}` — 괄호를 지운다. 마지막 성공은 라벨에 있다.
  - 첫 실행 없음: `… — {label} · 다음 실행 {next}` — 1999 날짜를 쓰지 않는다.
  - 실패: `… — {label} · 마지막 실행 {last} 뒤 {h}시간` — 라벨에 '다음 실행 없음'이 있으면 반복하지 않는다.
- `[:140]` 자르기는 남기되, ` · ` 경계에서 자르고 `…` 을 붙인다. 숫자·시각 중간은 자르지 않는다.
  - 다른 사유도 이름이 길면 같은 일이 난다(**추정**).
- 확인: 조용한 누락 픽스처로 결재함 1440·320 을 한 장씩 찍는다. 목적 줄이 온전히 끝나는지, 잘렸다면 경계에서 `…` 로 끝나는지 본다.

**근거**
- CLAUDE.md "숫자 표기·판정 표시" 원칙. 여기서는 금액이 아니라 시각이라 강도가 낮다.
- 1회차 메모 1.
- 결재함은 오너가 오늘 결정할 것을 읽는 자리다.

**담당**
- backend-engineer: org_runtime 예약 작업 경보 `make(… reason="task" …)` 의 `purpose`, `open_list` 의 `[:140]`
- qa: 픽스처로 확인한다.

### #2 표의 주황이 세 뜻이다 — '첫 실행 없음'(경보)과 '아직 때가 안 됨'(대기)이 같은 칩·같은 행 색

**화면·요소:** 예약 작업 표의 칩과 행 배경(`schedState` 의 ③·④·⑤ 분기)

**현재** — 캡처와 코드로 확인했다.
- after-sched-1440 과 after-quiet-sched-1440 에서 monthly '첫 실행 없음' 바로 아래에 db-backup-pull '아직 때가 안 됨'이 있다.
  - 두 행 모두 주황 칩이고 late 배경이다.
  - measure JSON 에서도 두 행 모두 `row:'late'`·`pcls:'pill warn'` 이다.
- 두 낱말이 모두 '한 번도 안 돎'을 말한다.
  - 하나는 결재함에 지시서가 서는 경보이고, 하나는 할 일이 없는 대기다.
  - 둘을 가르는 것은 칩 아래 사유 줄이 있느냐 없느냐뿐이다.
  - '실행 중'도 주황 칩이다.
- 타일은 대기를 중립으로 둔다.
  - `schedTile` 은 볼 것 없이 대기만 있으면 부제 'N개는 첫 실행 대기(예정일 있음)', 색 `''` 이다.
  - `heartbeatTile` 위 주석도 "첫 실행 대기 = 중립" 이다.
  - 그래서 타일의 주황은 경보 하나를 뜻하는데, 표의 주황은 경보·대기·실행 중 셋을 뜻한다. 주황 타일을 보고 표에서 주황을 찾으면, 셋 중 무엇인지 글자로 가려야 한다.
- 이 모양은 **내 1회차 처방**("행 클래스는 `late`(주황 배경)로 둔다")이 만든 것이다.
  - 1회차 캡처에는 이 표가 없어서 '아직 때가 안 됨'이 같은 톤이라는 것을 못 봤다(1회차 §0).
- 대기를 주황으로 둔 이유는 표 렌더 위 주석에 있다: "등록 직후의 heartbeat 가 '아직 때가 안 됨' 상태라 흐름 타일과 같은 순간에 눈에 띈다(design-critic 2026-09-27)".
  - 이제는 대기가 한도를 넘으면 규칙이 '첫 실행 없음' 경보로 올린다.
  - 그래서 대기 자체가 경고 톤일 필요가 줄었다.

**목표**
- 표의 주황 칩 + late 행은 '결재함 예약 작업 경보와 같은 판정'(`silence.bad`) 하나로만 쓴다.
- '아직 때가 안 됨'은 결재함 상태 '대기'와 같은 `pill idle`(무채색)로 바꾸고 행 클래스를 없앤다. 타일의 '첫 실행 대기'(중립)와 같은 톤이 된다.
- '실행 중'은 선택이다. 결재함 '진행'이 `pill ok` 이니 그쪽으로 가거나 idle 로 둔다. 최소 요구는 '아직 때가 안 됨' 하나다.
- 표 렌더 위 주석 "행 배경은 칩과 같은 심각도 — '아직 때가 안 됨'·'조용히 안 돎'(주황 칩)…" 을 새 규칙으로 고친다. `test_ops4_r2_dashboard` 의 칩 고정값도 바꾼다.
- 확인: 같은 데이터로 1440 을 찍어, 주황 칩이 경보 3행뿐인지 본다('실행 중'을 남기면 그 행까지).

**근거**
- 1회차 #1 의 원칙 "같은 목록·같은 규칙"을 톤에도 적용한 것이다.
- 이 화면의 원칙 "주황 타일은 결재함 하나로 둬야 '오늘 볼 것 = 결재함'이 한눈에 선다"(`kpi('열린 지시서'` 위 주석).

**담당:** frontend-engineer — `schedState` ④ 한 줄, 주석, 테스트 고정값

**목표**
- 구분자를 앞 조각 안에 넣는다: `<span class="seg">마지막 성공 09-25 15:59 ·</span> <span class="seg">…</span>`. 그러면 줄은 조각 사이 공백에서만 갈린다.

## ④ 잘된 점

1. **판정을 다시 짜지 않았다.**
   - `schedState` 는 `s.silence` 를 읽기만 하고, 서버는 순환계 `silence_rows` 를 그대로 싣는다. 결재함과 표가 다른 말을 할 구조가 없어졌다.
   - 테스트가 양쪽 방향으로 고정한다: '표가 초록이면 순환계도 경보 아님', '경보면 초록 아님'.
2. **칩 머리 + 사유 줄 = 결재함 라벨 글자 그대로.**
   - 1회차 목표문은 라벨 전체를 칩 한 덩이에 담으라고 했다. 이번 구현은 칩을 짧게 두고 이유를 아래에 적어 표 폭을 지켰다. 목표문보다 낫다.
3. **'확인 불가'를 초록으로 그리지 않았다.**
   - 지시 밖이지만 이 화면의 원칙 "정상 < 확인 불가 < 이상 < 멈춤"과 맞다.
   - 되돌리기는 한 줄이라고 스스로 적었다.
4. **타일 부제가 볼 것을 가리지 않는다.** 전에는 가장 심한 하나('1개 실패')만 적었다. 항목마다 nowrap 이라 좁은 폭에서도 낱말이 갈리지 않는다(after-kpis-320 확인).
5. **사유 줄에 `--faint` 대신 `--soft`(7.84:1)를 썼다.** 조치할 행의 이유가 AA 아래로 흐려지지 않았다.
6. **검증이 공정하다.**
   - 수정 전 캡처를 라우트 가로채기로 같은 서버·같은 데이터에서 찍었다.
   - 캡처에서 잡아 고친 것 3건을 스스로 적었다: 이름·날짜 칸 두 줄, '매 / 일', '확인 / 불가'.
   - inbox 해시 차이가 변경의 증거가 아니라고 스스로 밝혔다.
   - HEAD 이동과 캡처 기준 커밋을 HEAD.txt 에 남겼다.
7. **피드 톤.** 1회차 #3 목표값 그대로 들어갔다. 경보·지시서·완료가 색으로 먼저 선다.
