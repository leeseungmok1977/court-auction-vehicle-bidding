## 4. 교정 — audit-verify-B 의 "P11 순서 의존" 진단

`reports/2026-09-27-audit-verify-B.md` §4 와 머리말 handoff 는 `test_p11_…[/vehicles?bucket=wait]` 가 "전체 스위트에서만 실패한다(단독 56 passed) … 순서에 의존하는 픽스처 문제" 라고 적고 frontend 에 인계했다.

- **확인된 사실**
  - frontend 스크래치 `ux8r2/edit_tests.py`(10:12:43)는 P11 을 `bucket=wait` 로 넣었다. 현재 파일(10:18)은 `bucket=lowconf` 다(주석 "픽스처 30건은 전부 lowconf 칸").
  - 테스트 픽스처와 같은 30건을 빈 임시 DB 에 넣으면 `bid_state` 가 `lowconf`("예상낙찰가 산출 불가 — 판정 보류")다. 그래서 `/vehicles?bucket=wait` 는 **카드 0, 2페이지 링크 없음**이다. 순서와 무관하게 **항상** 실패한다.
  - `bucket=lowconf` 는 카드 12, 2페이지가 있다. 현재 P11 은 단독(2 passed)과 전체 스위트 둘 다 통과한다.
- **추정**: audit-B 의 전체 실행은 10:12~10:18 판(`wait`)을 수집했고, 단독 실행은 그 뒤 판(`lowconf`, 56건)을 돌렸다. 그러니 "순서 의존"이 아니라 **판이 달랐던 것**이다.
- **결과**: 그 인계("커밋 전에 픽스처를 독립시킨다")는 **이미 해소**됐고 더 할 일이 없다. 단 frontend r2 보고서에는 이 파라미터 교체가 적혀 있지 않다(보고 누락, 낮음).

## 5. UX-8 과 무관한 기존 결함 (별도 티켓 후보)

**목록 페이지 이동 줄이 카드(`overflow:hidden`) 밖으로 잘린다 — 큰글씨에서는 `다음 ›` 에 닿을 수 없다.** HEAD 로 확인했고 r2 는 좌표까지 같다. frontend r2 가 "화면은 열어 보지 않았다"고 남긴 관찰을 재현한 것이다.

| 조건 | 결과 |
|---|---|
| 큰글씨 360, 2페이지(카드 오른쪽 끝 340) | `97` 298..345 일부 잘림 · **`다음 ›` 350..407 전부 밖** |
| 큰글씨 360, 1페이지 | `다음 ›` 307..364 일부 잘림 |
| 큰글씨 320·390 | 좌표가 같아 같은 증상이다(320 은 더 심함) |
| 일반 320, 2페이지(카드 끝 304) | `다음 ›` 282..328 일부 잘림(`디` 만 보임) |

- 가로 스크롤은 없다(`#appscroll`·카드가 `overflow-x:hidden`). 사용자는 밀어서 꺼낼 수 없고, 숫자 링크로만 우회할 수 있다.
- 캡처: `pre-existing-pagenav-360-large-p2-head.png`(`74859d3e`)·`-p1-`(`d486b4d6`)·`pre-existing-pagenav-320-p2-head.png`(`b7d86ab2`). 열어 확인했다.
- ⚠ 측정 함정: 처음에 `scrollIntoView` 로 줄을 화면에 올렸더니 `overflow:hidden` 카드가 프로그램으로 가로 스크롤돼 `다음 ›` 가 282..339 로 **보이는 것처럼** 찍혔다. 그 캡처는 지웠고, 세로 스크롤만 해서 다시 찍었다.
- 영향(추정): 큰글씨를 켜는 사용자 층(패널 35·58세 맥락)이 목록 넘기기에서 막힌다. 금전 위험은 없다.

## 6. 한계

- MO 방식은 **headless Chrome 153 에서만** 검증했다. 실기기(TWA·안드로이드 Chrome·삼성 인터넷)는 미검증이다. "관찰 콜백은 렌더링 전에 돈다"는 명세 근거와 측정이 받치고, 엔진 소스는 보지 않았다.
- CPU 4배 측정 중 r1·HEAD 구간 일부는 캡처·넓은 폭 비교와 **동시에** 돌았다(부하가 더 걸린 조건). r2 구간은 마지막 한 화면(390 큰글씨·조건 없음)의 끝만 캡처 작업과 겹쳤다. 부하는 결함이 나올 확률을 높이는 쪽이므로 r2 의 0 을 약하게 만들지는 않는다(추정).
- 디자인 검수 원문을 받지 못했다(§1-4).
- 분할 전송은 0.8초 정지로 파서 양보를 결정적으로 만든 최악 사례다. 실제 망의 분할 위치 분포는 재지 않았다.
