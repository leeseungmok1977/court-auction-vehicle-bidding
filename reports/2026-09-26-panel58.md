# PANEL-58 — 시세 있는 리포트가 320·360px 에서 가로 스크롤 +91px (작업 지시서 2026-09-26-02)

담당 frontend-engineer · 커밋·배포 안 함 · 운영 DB 쓰기 없음(스크래치 사본 + sqlite `mode=ro`)

## 요약
+91px 의 주범은 **섹션 칩이 아니라** 칩 줄 오른쪽의 '더 있음' 표식
`<i class="secnav-more material-symbols-outlined" aria-hidden="true">chevron_right</i>` 다.
Material Symbols 아이콘 폰트가 적용되기 전(또는 못 받았을 때) 리거처 이름 `chevron_right` 가 13글자 낱말로
그려져 `width:20px` 상자를 뚫고 나가고, 그 상자가 바의 오른쪽 여백 끝(`right:-20px` = 뷰포트 끝)에 걸려 있어
문서가 **폭과 무관하게 정확히 그만큼** 넓어졌다(320→411, 360→451). 수정은 `.secnav-more{…}` 규칙에
`overflow:hidden` 한 선언(+ 이유 주석). 수정 후 3물건 × 6폭 + 큰글씨 + 폰트 차단 최악 조건 전부 `scrollWidth == 뷰포트`.

## 확인된 사실 (전부 로컬 재현 — uvicorn 127.0.0.1:8058, DATA_DIR 스크래치 사본, NC_NO_SCHEDULER=1 NC_NO_BACKGROUND=1, `X-Forwarded-For: 203.0.113.9`, UA 갤럭시 A53, DSF 2)

1. **재현**: 수정 전 `2026타경50403_1` /report 320px 첫 콜드 로드에서 `scrollWidth 411 / clientWidth 320` (+91) — 지시서 수치와 동일.
2. **비결정적**: 같은 조건을 다시 열면 0. 같은 칩 배치(`절차` 칩 L257 R296, `.secnav` scrollWidth 294 / clientWidth 280)인
   `2026타경100613_1` 320px 은 처음부터 0 → **칩 배치만으로는 설명되지 않는다.**
3. **요소 rect 로는 안 잡힌다**: 뷰포트 밖 요소는 `a[href="#sec12"]` (R326) 하나뿐인데 이것은 `nav.secnav`(`overflow-x:auto`)
   **안**이라 문서 폭에 기여할 수 없다. 지시서의 "원인 요소" 지목은 측정기가 요소 rect 만 세서 나온 **오귀속**이다.
4. **결정적 재현**: `**/*.woff2` 를 차단(폴백 폰트)하면 320→411, 360→451, `2026타경100613_1` 도 411, 큰글씨도 동일. 시세 없는 `2025타경73637_1` 은 0.
5. **범인 특정(자식 숨기기 이분탐색 + 텍스트 노드 rect)**: `div.page > div.rtop.no-print > div.secnav-wrap.can-scroll > i.secnav-more`,
   텍스트 노드 `"chevron_right"` 의 오른쪽 끝 = 411(@320) / 451(@360). 상자 `.secnav-more` 는 20px, 글자 줄은 약 111px(18px 폴백).
6. **정상 로드에서도 창이 있다**: rAF 로거로 콜드 로드 시간축을 찍으면 `t=564ms fonts=loading` 에 411, `t=691ms` 에 320 으로 복귀.
   워크플로 -14 는 이 창(또는 폰트 미도착 환경)에서 측정한 것이다. 워크플로가 360 에서도 +91 을 본 이유: 폴백 폰트에서는 칩이 더 넓어
   360 에서도 `.can-scroll` 이 켜져 표식이 `display:block` 이 된다(로드 완료 폰트에서는 360 에 칩이 다 들어가 표식 자체가 안 뜸).
7. **왜 시세 없는 물건은 6폭 0 인가**: 바 전체가 `{% if report %}` 안이다(`service.report_data` 가 `effective_median`/`median_price`
   없으면 `None`). 고쳐서 0 이 아니라 **안 그려서** 0 이다 — 테스트에 반증으로 못 박았다.
8. **기존 가드로는 안 된다**: `html.ms-pending .material-symbols-outlined{visibility:hidden}`(tailwind_input.css, base.html 전용 — report.html 은
   base 를 상속하지 않아 애초에 안 붙음)과 `@font-face … font-display:block` 은 글자를 **안 보이게** 할 뿐 자리는 차지한다.
9. **수정 후**: 아래 측정표. `npm run build:css` 실행 → `web/static/app.css` md5 `bcfe1da650e1bc197c0871e379277c77` 전후 동일(바이트 비교 IDENTICAL).

## 수정 (web/templates/report.html 인라인 `<style>`, 앵커 `.secnav-more{`)
```
-.secnav-more{position:absolute;right:-20px;width:20px;…;display:none;line-height:1}
+/* PANEL-58 — overflow:hidden 은 **아이콘 폰트가 오기 전의 리거처 이름** 때문이다. … */
+.secnav-more{position:absolute;right:-20px;width:20px;…;display:none;line-height:1;overflow:hidden}
```

- 왜 이것이 최소인가: 글리프 `›` 는 1em(18px) 이라 20px 상자 안에 들어간다 → 잘리는 것은 **폰트 없을 때의 글자 줄뿐**.
  `.secnav-wrap` 이나 `.rtop` 에 overflow 를 걸면 여백 위의 표식 자체와 칩 포커스 링이 잘린다. 시각 결과가 픽셀 단위로 같음은 아래 zoom md5 로 확인.
