  - 서버가 그린 카드는 4장(점 4개)입니다. id 는 `2026타경50731_1 · 2025타경12604_1 · 2026타경50344_1 · 2026타경30698_1` 로 auditor 와 같습니다.

## 3. 추가 발견 N1 — bfcache 복귀 시 목록이 스켈레톤으로 고착 (높음)

**왜 지금까지 안 보였나**
- Playwright 는 Chromium 을 `--disable-back-forward-cache` 로 띄웁니다. 설치된 드라이버의 chromiumSwitches 에서 확인했습니다.
- 그래서 우리 Playwright 흐름의 뒤로가기는 모두 새 로드였습니다.
  - auditor 가 기록한 navtype `back_forward` 자체가 새 로드였다는 증거입니다. bfcache 로 복원되면 원래 항목인 `navigate` 와 `persisted=true` 가 나옵니다.
  - tests/ 에는 bfcache·persisted 언급이 0건입니다.
- 안드로이드 Chrome 은 bfcache 가 기본으로 켜져 있습니다.

**재현** — `ignore_default_args=['--disable-back-forward-cache']` 만 바꿨습니다.
- E(390, 펼침, SW 허용): 4394 → '2' → 뒤로
  - 뒤로 갈 때 문서 요청이 없었습니다(bfcache).
  - `pageshow persisted=true`, `#listResults.hidden`, `#listSkeleton` 보임
  - 화면은 회색 줄 8개와 '총 159건'뿐이고, 페이지 이동 줄이 없습니다(`QA-P2-390-bfcache-expanded-02-after-back.png`).
- F1(360, 접힘, SW 차단): 같은 결과였습니다.
  - 뒤로 간 뒤 2.5초와 8초에 두 번 읽었고 둘 다 스켈레톤이었습니다.
  - CDP `Page.backForwardCacheNotUsed` 는 0건이었습니다(bfcache 가 쓰였다는 뜻).
  - 캡처: `QA-P2-360-bfcache-folded-03-after-back.png`

**원인**
- show() 가 떠나기 직전 DOM 을 스켈레톤 상태로 바꾸고, 그 DOM 이 bfcache 에 저장된 채로 돌아옵니다.
- vehicles.html 에서 `pageshow` 를 듣는 코드는 [적용] 버튼의 `mark(false)` 하나뿐이고, show() 를 되돌리는 코드가 없습니다.
- 지적 2를 고쳐 스크롤 저장이 맞게 되어도 이 고착은 남습니다. `pageshow`(persisted)에서 되돌리는 코드가 따로 있어야 합니다.

**사용자에게 보이는 것**: 1페이지 → 2페이지 → 뒤로 가면 목록이 비고 회색 막대만 남습니다. 새로고침하거나 다른 곳으로 이동하기 전에는 복구되지 않습니다.

**한계**
- 헤드리스 데스크톱 Chrome 153 에서 모바일 에뮬레이션으로 확인했습니다.
- **실기기 안드로이드 Chrome·TWA 는 검증하지 않았습니다.** 실기기는 bfcache 적격 조건이 다를 수 있습니다.
