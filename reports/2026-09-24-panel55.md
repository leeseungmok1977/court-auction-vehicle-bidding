## 1. 바꾼 문구 원문

위치: `web/templates/report.html`, `{% if report %}` 본문의 `{% else %}` 가지. 앵커 `시세가 아직 산정되지 않아`.
판정은 새로 만들지 않고 기존 `is_admin(request)` 하나를 쓴다 — `app.py` 가 `templates.env.globals["is_admin"]` 로
등록해 두었고 `report.html` 은 이미 `{% if v.comps and is_admin(request) %}` 로 쓰고 있었다. **라우트 변경 없음.**

| 보는 사람 | 문구 |
|---|---|
| 관리자(`is_admin` 참 = XFF 없음 + loopback) | **유지**: `시세가 아직 산정되지 않아 종합 리포트를 생성할 수 없습니다. 물건 상세에서 [다시 분석] 후 다시 시도하세요.` |
| 공개(XFF 있음) | **신규**: `시세가 아직 산정되지 않아 종합 리포트를 만들 수 없습니다. 감정가·최저매각가 등 법원 자료는 물건 상세에서 그대로 확인하실 수 있습니다.` |

### 초안의 두 번째 문장("시세가 잡히면 이 화면에서 바로 열립니다")을 쓰지 않은 근거

- **글자 그대로는 참이다(확인된 사실).** `vehicle_report`(app.py)는 요청마다 `db.get_vehicle` → `service.report_data()` 를 새로 계산하고,
  HTML 응답에 캐시 헤더가 없다. `median_price` 가 생기면 다음 요청부터 `{% if report %}` 가 열린다.
- **그러나 "시세가 잡히면" 이 대다수에겐 오지 않는 조건이다(확인된 사실).** 자동 경로는 `daily_update` ②-0b →
  `requery_missing_market(within_days=30)` 하나뿐이고, 대상은 `db.list_vehicles(upcoming_days=within_days)` —
  **기일이 오늘~+30일인 물건만**, 낙찰·종결·상세없음 제외, `year` 필요, `encar.auto_map` 성공 필요, 7일 백오프, 런당
  `requery_daily_cap`(기본 20그룹), 엔카 차단 중이면 건너뜀.
- **실측(§2 모집단 431건)**: 기일 지남 **391** · 연식 없음 1 · 매핑 실패 4 → 재조회 적격 **35건(8.1%)**. 이 35 는 백오프·일일
  상한·차단을 적용하지 않은 **상한값**이다. 라이브 재현 2건(`2025타경56677_1`·`2026타경50409_1`)은 둘 다 `2026-08-18` 낙찰·종결로
  **영구 제외** 대상 — 그 화면에 "시세가 잡히면" 을 적으면 오지 않을 것을 기다리게 한다.
- 대신 넣은 문장의 근거: 431건 **전부** `appraisal_value`·`min_sale_price` 보유(NULL/0 = 0건). "사진" 을 넣지 않은 이유는
  `photo_count` 0 이 11건이라서다. 어휘는 `detail.html` 의 같은 상태 배너
  (`감정가·최저매각가·사진 등 법원 자료는 그대로 확인하실 수 있습니다`)에 맞췄다.
- "물건 상세" 를 링크로 만들지 않은 이유: 리포트 상단 고정 바에 `상세로` 버튼이 이미 있고, 그 버튼은 `_reportBack()` 으로
  **히스토리를 늘리지 않게** 설계돼 있다(report.html 주석 "'상세로'는 히스토리를 늘리지 않고 되돌아간다"). 본문에 일반 링크를
  더하면 그 설계를 우회하게 된다.

## 2. 발생 범위 — 모집단을 먼저

**모집단 = 공개 목록이 실제로 보여주는 물건 1,163건(`list_vehicles(hide_incomplete=True)` 의 WHERE 를 그대로 옮김).
그중 431건(37.1%)이 이 분기를 탄다 — "사용자가 마주치는 수" 는 이쪽이다.** 전체 `vehicles` 1,418건 기준으로는 684건(48.2%) —
이 수는 `(병합)`·`상세없음`·미완 수집분을 포함하므로 사용자 수치로 쓰지 않는다.

| 모집단 | 전체 | 시세 없음(`median_price IS NULL`) | 비율 |
|---|---:|---:|---:|
| `vehicles` 전체(무필터) | 1,418 | 684 | 48.2% |
| **공개 목록(`hide_incomplete=True`)** | **1,163** | **431** | **37.1%** |
| 공개 목록 ∧ 기일 미도래(오늘 이후, 낙찰·종결·상세없음 제외) | 144 | 40 | 27.8% |

- 분기 조건(코드): `report_data()` 는 `effective_median(v) or v.get("median_price")` 가 거짓이면 `None` → 템플릿 `{% if report %}` 의 else.
  `effective_median` 은 블렌드도 `median_price` 가 있어야 하므로 **`median_price IS NULL` 과 동치**. `median_price = 0` 행은 0건.
- ⚠ 닿는 경로가 좁다(확인된 사실): **`detail.html` 은 `median_price` 가 None 이면 리포트 링크를 아예 그리지 않는다**
  (헤더 `{% if v.median_price is not none %}` 버튼, 본문 '총 취득원가' 안내 링크 둘 다). 다른 템플릿엔 `/report` 링크가 없다.
  즉 공개 사용자는 **직접 URL·과거 공유 링크·검색엔진 유입**으로만 이 화면에 닿는다. 431 은 "닿으면 보이는 수" 이지
  "앱이 안내해서 가는 수" 가 아니다. 그래도 고쳐야 하는 이유: 닿으면 100% 이 문구가 나오고, 낙찰·종결 118건은 공유·검색으로 남아 있다.
- 측정 조건: `data/auction.db` 로컬 사본(mtime 2026-09-23 15:27) · `sqlite3` `mode=ro` 직접 열기(`web/db.py` import 안 함, 마이그레이션 0) ·
  오늘 = 2026-09-24(sqlite `date('now','localtime')`) · glob+sqlite 한 프로세스.
