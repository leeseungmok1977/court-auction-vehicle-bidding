## A. U1 판정 — 탭 `차량목록`은 "마지막으로 본 목록"으로 돌아가야 한다
**판정: 복귀형이 맞다.** 근거 셋.
1. **같은 목적지에 두 규칙이 있다.** 상세 [←]와 브라우저 back 은 필터·2페이지·스크롤 2227px 까지 복원한다(S3-18 이 S1-05 와 동일 화면, S2-14). 하단 탭 `차량목록`은 같은 `/vehicles` 로 가면서 전부 버린다(S3-20 = S1-01 md5 동일). 신뢰를 깎는 것은 어느 한 정책이 아니라 **예측 불가**다.
2. **상세 화면의 하단 탭이 `차량목록`을 '현재 위치'로 표시한다**(S3-17). 활성 탭을 누르는 행동은 어느 앱에서나 "내가 있던 섹션의 화면으로"다. 그 탭이 초기화라는 것은 활성 표시가 한 약속을 깨는 것이다.
3. **재진입 비용이 크다.** 왕복 한 번마다 셀렉트 3 + [적용] + [2] + 스크롤 = 6동작. 서버는 이미 `last_list` 쿠키를 갖고 있고 상세 [←]가 그 값을 쓴다 — 재료가 있는데 한 경로만 쓴다.

**"새로 시작하고 싶은 사용자"를 놀라게 하지 않는 장치 (넷 모두 필요):**
- ① **세션 한정 복귀.** 같은 브라우저 세션(또는 짧은 TTL, 예 30분) 안에서만. 다음날 다시 열면 깨끗한 최근 등록순. 영속 조건은 이미 `검색 저장`이 맡고 있다(S5-27).
- ② **활성 탭 재탭 = 맨 위로.** 이미 목록에 있을 때 `차량목록`을 다시 누르면 스크롤만 맨 위로(모바일 관례).
- ③ **`필터 초기화` 칩 상시 노출.** 지금은 0건 빈 상태 블록 안에만 있다. 활성 필터가 하나라도 있으면 칩 줄 맨 앞 `검색 저장` 옆에.
- ④ **복귀 직후 인라인 요약 한 줄.** `총 159건` 위에 "현대 · 1,000~2,000만 · 매각기일순 · 2페이지 · [초기화]". 토스트가 아니라 남아 있는 줄 — E1 의 해법과 같은 요소다.
- 덧: 상세 [←]에 "목록으로" 텍스트 라벨. PC 프레임 F5(U4)도 같은 가족 — `frame.html` 바깥 해시를 iframe 이동마다 갱신하면 함께 풀린다.

## B. U2·U3 의 사용자 체감
**U2 — 모수가 조용히 바뀌는 것은 이 제품 신뢰의 근간을 친다.** S11-54→55: 조건을 하나 **더** 걸었는데 건수가 **늘었다**(88→128). S11-56→57: 정렬 하나 바꿨는데 전체 DB(1,316)가 그날 목록으로 둔갑한다. 이 제품이 신뢰의 근거로 삼는 것은 "같은 조건이면 숫자가 어디서나 같다"(159=159=159)다. 이 두 경로는 **사용자가 하지 않은 조작**으로 숫자를 바꾼다. 무음이라 더 나쁘다. 체감 심각도: **높음**.
**U3 — 줄바꿈의 시각적 심각도: 중, 위치 때문에 중상.** S11-56: `2026-` / `09-01` / `매각 ✕` 3줄, 날짜가 하이픈에서 갈려 날짜로 읽히지 않는다. 검색창 바로 아래 칩 줄은 "지금 무엇으로 걸러져 있나"를 확인하는 곳 — 필터 상태 표면이 깨져 보이면 필터 자체를 의심한다. 고치는 비용은 클래스 하나.

## C. U5 `매각기일순` — 권고: **정렬 순서를 바꾼다.** 라벨 변경·`입찰예정` 짝짓기는 택하지 않는다.
- 현재: `sort_cols["sale_date"] = "sale_date"` → 지난 기일이 앞. 12건/페이지(라이브 페치 `13–24 / 총 159건`)라 눈에 보이는 24건이 전부 끝난 경매다.
- 왜 순서 변경인가: **라벨만 바꾸면** 정직하지만 불편은 그대로. **`입찰예정`과 짝지으면** 159→51로 모수가 사용자가 고르지 않은 조건으로 바뀐다 — U2 와 같은 죄를 설계로 저지르는 것. **순서 변경**은 모수(159)를 유지하고 라벨의 기대를 지키며 끝난 경매도 뒤에서 참고할 수 있다.
- 목표 순서: 오늘 이후 → 가까운 순, 그 뒤 지난 기일 → **최근 종료가 먼저**. 경계에 얇은 구분 줄 "지난 기일 · 낙찰 결과 N건". 라벨은 `매각기일순` 그대로 또는 `매각기일 가까운순`.

## D. U6·U7·U8·U9
- **U6 미적용 변경 무음 소실 — 있다(작게).** 변경이 있으면 [적용]을 채움(primary)으로 바꾸고 상태를 말한다. 자동 제출은 권하지 않는다.
- **U7 검색어 지우는 손잡이 없음 — 있다.** 검색어 활성 칩 `쏘나타 ✕` + `type="search"`.
- **U8 큰글씨 접힌 머리 무표시 — 있다.** 접힌 머리에 "현대 · 1,000~2,000만 · 매각기일순" 한 줄 — A-④·E1 과 같은 요소를 재사용.
- **U9 초기화가 정렬까지 — 없다.** 초기화 후 상태가 첫 진입과 같은 것은 예측 가능하고 설명이 필요 없다(S10-02 = S1-01).

## E. qa 가 못 본 것 (3건)
**E1. 활성 조건을 말하는 표면이 반쪽이고, 초기화·페이지 위치도 제자리에 없다.** S1-03: 걸린 조건은 셋인데 칩 줄에는 `1,000~2,000만 ✕` 하나. 진입 파라미터 칩(`유망 물건 11 ✕`, `신뢰도 낮음 108 ✕`, `입찰예정 30일 ✕`)은 칩이 되는데 사용자가 직접 고른 조건은 칩이 안 된다 — 규칙이 뒤집혀 있다. `필터 초기화`는 0건 빈 상태에만. 현재 페이지 위치는 마지막 카드 뒤에만.
**E2. `짧은 주행거리순` 첫 자리에 주행거리가 없는 물건.** S11-57: 첫 카드 `동력선 진솔호`, km 표기 없음. 코드는 NULL 뒤로이므로 0 저장으로 보인다 — 확인 필요. 목표: 0 도 NULL 과 같이 뒤로.
**E3. 셀렉트 옵션의 괄호 건수가 적용 전 조합을 반영하지 않는다.** S1-02: 현대 선택(미적용)에서 `1,000~2,000만 (451)` → 적용 후 `(159)`. 괄호 숫자는 약속처럼 읽힌다. 목표: 셀렉트 변경 시 건수 재계산, 또는 "현재 조건 기준" 명시, 또는 괄호 제거.

## F. 지적 5건 (우선순위순)
**지적 1. 하단 탭 `차량목록`이 상태를 버리고, 상태를 지키는 유일한 손잡이는 아이콘 전용 [←] 하나다 (U1 + U4)** — 목표: 탭 → `last_list`(세션 한정) 복귀 + 활성 탭 재탭 = 맨 위로 + `필터 초기화` 칩 상시 + 복귀 직후 조건 요약 한 줄. [←]에 "목록으로" 텍스트. PC 프레임은 iframe 이동마다 바깥 해시 갱신. 근거: S1-07/09/11 ×3, S3-20, S8-45, S3-17, S3-18, S2-14, S9-18.
**지적 2. [적용]이 `segment`·`date`(·`court`)를 버려 모수가 사용자가 하지 않은 조작으로 바뀐다 (U2)** — 목표: hidden 또는 병합 제출. 회귀 테스트: 진입 파라미터 전 종류 × [적용] 후 총수 불변. 근거: S11-54~57, S11-51/53(대조).
**지적 3. 정렬 두 종이 이름과 반대로 동작한다 — `매각기일순`은 끝난 경매부터, `짧은 주행거리순`은 주행거리 없는 물건부터 (U5 + E2)** — 목표: 매각기일순 = 오늘 이후 가까운 순 → 지난 기일은 최근 종료가 먼저, 경계 구분 줄(모수 유지, `입찰예정` 자동 짝짓기 금지). 주행거리순 = NULL 과 0 모두 뒤로. 근거: S1-03, S1-04, S1-05, S11-57, `db.py` `sort_cols`.
**지적 4. 활성 조건을 말하는 표면이 반쪽이고 깨져 보인다 (E1 + U3 + U7 + U8)** — 목표: (a) 활성 칩 전부 `whitespace-nowrap shrink-0` (b) 제조사·판정·정렬·검색어도 활성 칩으로, 또는 `총 N건` 위 요약 한 줄 (c) 그 한 줄을 큰글씨 접힌 머리에도 재사용 (d) 검색창 `type="search"`. 근거: S1-03, S4-12-M360, S6-30, S11-54, S11-56, S8-41.
**지적 5. 적용 전 단계가 정직하지 않다 — 옵션 건수는 옛 조건 것, [적용] 버튼은 변경을 모른다 (E3 + U6)** — 목표: 셀렉트 변경 시 옵션 건수 재계산(불가하면 "현재 조건 기준" 명시 또는 괄호 제거). 변경이 있으면 [적용]을 primary 채움 + "변경 적용". 근거: S1-02, S1-03, S10-01, S7-37, S7-39.
