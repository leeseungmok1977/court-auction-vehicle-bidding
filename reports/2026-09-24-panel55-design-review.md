## ② 고칠 것 — 3건(우선순위순)

### 지적 1. 마스트헤드 `낮음` 배지 — **판정 표시 문제**(표기 문제가 아니다)
- 현재: 공개 5장·관리자 1장 **전부** 마스트헤드 우상단에 외곽선 알약 `낮음` 이 홀로 찍힌다. 명사가 없다 — 명사를 주는 첫 배지 `시세 신뢰도 NN/100` 은 `{% set conf = v.market_confidence or 0 %}` + `{% if conf %}` 로 숨고, `{{ v.market_confidence_label or '—' }}` 만 남는다. 출처: `src/parse/market_match.py` `_confidence_label` — `median_price is None` 이어도 라벨을 계산하고 confidence 기본 0 → **"낮음"**. 우연이 아니라 **이 분기 전건(공개 431건)** 이 `낮음` 을 단다.
- 왜 문제인가: 앱의 판정 단일 소스가 그 둘을 일부러 갈라 놓았다 — `service.py` 주석 *"신뢰도 낮음은 '비교했는데 못 믿겠다', 이쪽은 '비교할 대상이 없다'"*. 재현 물건(매각기일 2026-08-18, 낙찰·종결)은 `bid_state` 가 `매각 종료` 를 내고 상세 h1 칩이 그걸 보여주는데, 리포트 마스트헤드는 `낮음` 이라 말한다. **같은 물건, 두 화면, 두 말** — '목록과 상세가 다른 말' 계열의 세 번째 자리. 시선이 먼저 닿는 위치의 데이터 상태 라벨이 거짓이므로 **판정 표시** 범주 → `app-design-expert`+`design-critic` 교차검수. (추정: 같은 줄의 34px 흰 정사각 `A` 브랜드마크가 점수 없는 페이지에서 `A` 등급처럼 읽힐 수 있다.)
- 목표: 라벨 배지를 점수 배지와 같은 게이트에 넣고, 시세 없는 분기에는 **`bidst.label`** 을 찍는다 — 리포트 라우트가 이미 넘긴다(`app.py` `"bidst": _bidst, # 판정 단일 소스 — 상세와 같은 값`). 마스트헤드가 상세 칩과 한 글자로 같아진다(`매각 종료` / `동급 시세 없음` / `지난 기일 — 다음 기일 공고 대기`). 색은 `.badge` 그대로(흰 외곽선, 의미색 없음). 긴 라벨은 `detail.html` 처럼 `ui.judge_label` 로 ' — ' 뒤에서만 접는다. 차선: `conf` 가 0이면 배지 자체를 안 그린다.

### 지적 2. 페이지의 유일한 본문이 각주 크기이고 **면책보다 연하다** — 담당 관찰 (a) 판정: 맞지 않다
- 현재: 문구는 `.note` = 11.5px / `--ink-faint` #5F6B7E, 390에서 3줄 316×55. 바로 아래 `.disc` 는 같은 11.5px 이지만 **더 진한** `--ink-soft`, 제목 굵게, 빨간 굵은 문장 "…**권장가는 무효입니다**". 마스트헤드(남색, 30px 제목)는 ≈420px, 본문 카드의 4.6배.
- 왜 문제인가: 시각 위계가 마스트헤드 > 면책 > **실제 메시지(페이지에서 가장 연한 글자)**. 가장 붉고 굵은 낱말이 **이 페이지에 없는 '권장가'** 를 말한다. 같은 상태를 상세는 제목 `text-xs font-semibold` + 본문 `text-sm`(14px)로 그린다 — 리포트만 각주다.
- 목표: 두 층으로. 첫 문장(사실) 14px/600/`--ink`, 둘째 문장(안내) 13px/400/`--ink-soft`. 새 CSS 없이 이미 있는 `.sec-empty`(12.5px·ink-soft·왼쪽 3px 레일, "자료가 없는 섹션 — 왜 비었는지를 본문에 적는다")로 바꾸고 첫 문장만 `<b style="color:var(--ink)">`. 큰글씨 모드 규칙 둘 다 이미 있다. **빨강·앰버 금지** — '해당 없음'이지 경고가 아니다.

### 지적 3. 문구 자체 — `아직` 한 낱말, 그리고 "물건 상세" 링크
- 현재: 공개 문구 첫 절 "시세가 **아직** 산정되지 않아". 이 분기 공개 431건 중 391건(90.7%)이 기일 경과. 같은 물건을 상세는 "매각 종료된 물건입니다 — 시세·입찰가는 계산하지 않습니다" 라고 현재형으로 말한다.
- 왜 문제인가: 담당이 "시세가 잡히면 열립니다"를 뺀 이유 그대로 — `아직` 은 한 낱말짜리 시점 약속이고, 열에 아홉에게는 '영영'이다.
- 목표: 공개 분기만 `아직` 삭제. 관리자 문구의 `아직` 은 유지(행동할 수 있는 사람). `test_public_copy_promises_no_timing` 금지어에 `아직` 추가.
- 링크 판정: 막다른 길의 반복은 **아니다** — `상세로` 가 sticky 바에 있어 같은 화면에 있다. 다만 문장은 "물건 상세", 버튼은 "상세로"라 한 번 더 찾게 한다. `물건 상세` 를 `<a href="/vehicle/{{ v.id }}" onclick="return _reportBack(event)">` 로 만들면 히스토리 설계를 우회하지 않으면서 손가락 밑에 출구가 생긴다 — 같은 핸들러 재사용. 배포를 막지는 않는다.

## ③ 잘된 점(유지)
1. **판정을 새로 만들지 않았다.** 버튼을 그리는 바로 그 술어 `is_admin(request)` 로 문구를 갈랐고, 테스트가 전제(버튼이 관리자 전용)를 감시한다.
2. **시점 약속을 취향이 아니라 모집단으로 거절했다.** "시세가 잡히면"이 참인지가 아니라 **누구에게 참인지**(35/431 상한)를 세어 뺐다.
3. **캡처 규율.** `HEAD` 병기, 11장 md5 상이, `<p>` bounding box 로 파일명↔화면 일치, XFF 자가검증, **기일 미도래 물건을 따로 찍어** 공허 통과를 피했다.
4. 320px 에서도 3줄로 자연스럽게 감기고 고아 줄 없음.

## 확인 필요(추측)
- 빈 리포트의 sticky 바에서 `되팔기` 토글은 대상 섹션이 없어 눌러도 무변화일 것이고 `PDF 저장` 이 유일한 주동작 — 리포트가 없는 페이지의 주동작이 '빈 리포트 저장'. 직접 눌러 보지 못함. 변경 영역 밖.
- 포터II(기일 미도래)가 `bid_state` 에서 `nomarket` 인지 `lowconf` 인지 실행해 보지 않았다 — 지적 1의 처방(`bidst.label`)은 어느 쪽이든 같다.
