## ② 고칠 것 — 우선순위순 3건 (담당 문장 요지)

### 1. 가린 자리 바로 옆에 '재판매 상한가'가 숫자로 남는다. 음수는 기준시세와 같은 길이의 초록 막대로 그려진다 — frontend(테스트 qa) · 이 배치 차단 아님(이미 운영) · Play 출시 전 권고
- 상세 '입찰가 산정 근거' 맨 아래 "= 손익분기 상한 -13,321,000" 이 초록(emerald-700), 막대 스타일 `width:{{ (v.upper_bid / base * 100)|round(1) }}%` 가 `width:-38.2%` 로 렌더 → CSS 가 무효로 버리고 auto(부모 전폭) — **막대가 100% 를 말한다.**
- 목록 lg 표·관심 표 '상한가 재판매' 칸 "-13,321,000"이 '예상낙찰가: 내지 않음' 바로 옆. 리포트는 같은 값을 "산정 불가(0원 이하)"로 쓴다 — 한 값이 세 화면에서 세 모양.
- 잠복 갈래: 키워드로만 '입찰 보류'가 된 물건은 `upper_bid` 가 양수(픽스처 KWFLOOD 19,000,000) → 상세·목록·관심에 정상 재판매 상한가가 선다(리포트는 막음). 테스트 헬퍼 `_withheld_amounts` 가 `upper_bid` 를 세지 않아 빨간불이 안 켜진다.
- **목표**: `upper_bid ≤ 0` 은 세 자리 모두 "산정 불가(0원 이하)", 초록·막대 없음(막대 폭은 0 이상으로 자른다). `no_estimate` 참이면 상한가 칸 '내지 않음', 상세 산정표는 차감 행은 남기고 마지막 줄만 '내지 않음 — 침수·전손 의심'.
- **확인**: FLOOD·KWFLOOD·FLDR2 + '비침수 음수 상한' 픽스처를 상세·목록(lg)·관심으로 렌더해 `width:-` 0건 · `_withheld_amounts` 에 `v.upper_bid` 추가 후 0 hits · 34408 산정 근거·목록 T 행·관심 T 표 390·1440 재촬영 · 홈 '유망 물건' 표의 '상한가 재판매' 칸도 확인.

### 2. 판정은 "입찰하지 마세요"인데, 같은 화면의 다른 신호가 반대로 읽힌다 — Steward 가 먼저 정함(a 표시 게이트, b·c 문구) · 차단 아님(전후 같음) · Play 출시 전 권고
- a. 리포트 01 육각형: 판정 상자 아래 '가격 메리트 100'·'잔존가치 38'·'유동성 84', 머리 "6/6축 산출" — 세 축 모두 판정이 이 차에 쓸 수 없다고 한 정상차 시세에 기댄 값.
- b. 리포트 '입찰 중단 기준' "…침수 확정 시 본 리포트의 권장가는 즉시 무효이며 입찰 보류를 권장합니다" — 권장가가 없고, 무조건 '하지 마세요'가 조건부로 약해진다.
- c. 상세 산정 근거 상자 "자동 산정을 제공하지 않으니 현장 점검 후 판단하세요" — 히어로 "입찰하지 마세요"와 다른 지시.
- d. 상세 히어로 '시세 신뢰도' 배지가 no_estimate 물건에도 신호등 색(리포트 `.masthead.is-stop` 규칙과 다름) — '높음' 침수차면 "입찰하지 마세요" 아래 초록 배지.
- **목표**: a 세 축 '미산출'+사유(→ "3/6축 산출"), b·c 판정 상자와 같은 지시·'권장가' 삭제(문구는 Steward), d 리포트 is-stop 과 같은 중립색.
- **확인**: FLOOD 리포트 01 세 축 '미산출'·'권장가' 0 · 상세 "판단하세요" 0 · '높음' 침수 픽스처 히어로 배지 emerald 0 · 390 캡처.

## ③ 잘된 점
1. REC-9 의 핵심 모순이 열어 본 모든 침수 화면에서 사라졌다 — 특히 관심 카드의 침수차 초록 '여유 +2,348,000' → '—'.
2. '내지 않음'(값은 있지만 내지 않는다)과 '미산출'(자료가 없어 못 냈다)을 갈랐다. 리포트는 번호를 건너뛰지 않고 회색 레일 한 줄로 이유와 "(01)".
3. 처리방침이 Play '수집 없음' 신고와 표면에서 어긋나지 않게 됐다 — '(예정)' 행 분리, 안전성 조치는 확인된 네 가지만, 개정 이력 날짜 고정 문자열·테스트.

## 확인 필요 (Steward 판단) — 담당 문장 그대로
- **배포 뒤 확인 대상으로 34408 을 쓸 수 없다.** 라이브 34408 은 10-01 현재 "매각 종료(참고용)"로 'AI 예상낙찰가 13,200,000원'을 그린다. `estimate_withheld` 는 매각 종료를 먼저 보기 때문에 끝난 침수차에서는 거짓이 된다. 배포 뒤에는 state=blocked 인 라이브 침수차를 골라 확인해야 한다. 그렇지 않으면 공허 통과다.
- **같은 이유로, 매각 중에는 '내지 않습니다'였던 침수차가 매각이 끝나면 예상가를 다시 그린다.** 그대로 둘지는 판단이 필요하다. 이미 입찰할 수 없는 물건이라 금전 손해는 없다.
- **상세 산정표의 초록 전폭 막대는 침수차만의 문제가 아니다.** 코드상 `upper_bid < 0` 이고 breakdown 이 있는 모든 물건에 그려진다. 해당 대수는 DB 로 세야 한다.
- 미검증: 전후 md5(눈으로만) · 6폭 넘침(담당 측정 의존) · 촬영 뒤 detail.html 수정의 렌더 영향 · 키워드 보류 물건 렌더(사본 0대) · §6-5 관심 칩 충돌 · 큰글씨·인쇄·실기기 · 오늘 캐러셀 구성.
