# UX-8 결과 화면 필터 카드 접기 — 디자인 검수 (2026-09-27-08 / app-design-expert)

- **검수 범위: 바뀐 부분만.** 대상은 `/vehicles` 좁은 폭(< 640) 결과 화면의 접힌 머리(summary), 접힌 칩 줄(`#listFilterChips`), 펼침 기억, 그리고 넓은 폭·큰글씨가 바뀌지 않았다는 약속이다. 전체 채점이 아니라서 루브릭 총점은 매기지 않았다.
- **본 캡처:** `screenshots/ux8/` 45장과 `HEAD.txt`(기준 커밋 `c7d38d0`, dirty = vehicles.html·app.css·테스트 6파일). **45장 전부 Read 로 열었다**(md5 기준 서로 다른 화면 28종). 이 자리에는 해시 도구가 없어 md5 를 다시 계산하지 않았다. HEAD.txt 값을 인용했고, md5 가 같다고 적힌 쌍은 눈으로 봐도 같은 화면이었다.
- **측정:** 다시 재지 않았다(지시). 수치는 `reports/2026-09-27-ux8-frontend.md` §2·§3 을 인용했다. 캡처에서 읽은 좌표는 눈대중이라 ±5px 오차가 있다.
- **라이브:** 요청하지 않았다(지시서 공통 규칙).
- **코드 근거(줄 번호 대신 앵커):**
  - `web/templates/vehicles.html` — `{% set _cs = namespace(` · `page ~ '/' ~ total_pages ~ '페이지'` · `_cs.parts|length - 1` · `{% macro filter_chips(with_quick) %}` · `id="listFilterChips"` · `nc:listFilterOpen` · `expand_more</span></summary>`
  - `web/templates/base.html` — `function ncToggleLarge()`
  - `web/templates/detail.html`·`dashboard.html` — `group-open:rotate-90`
- **표기:** **[캡처]** 캡처에서 본 것 / **[코드]** 템플릿에서 읽은 것 / **[보고서]** 프론트 보고 인용 / **[추정]** 근거를 대지 못한 것.

## ① 배포 가능 여부 — **배포 가능**

- **목표를 달성했다.** 390×844 에서 첫 카드의 최저매각가 줄이 탭바 뒤(891)에서 첫 화면 안(614)으로 올라왔다 [보고서 §3]. `after-390-cond.png` 에서도 `14,000,000` 이 약 y601 로 탭바(약 y787) 위에 있다 [캡처]. 320 에서도 온전하다(`after-320-cond.png` 가격 줄 약 y620) [캡처].
- **바꾸지 않겠다는 약속을 지켰다.** `after-768-cond/date/plain`·`after-1440a-*`·`after-large-360-*` 를 before·headre 와 눈으로 비교하면 같은 화면이다 [캡처]. md5 도 일치하고, 예외 768-plain 은 대조군으로 설명됐다 [HEAD.txt·보고서 §4].
- **깨진 것이 없다.** 폰 4폭·PC 프레임 캡처 어디에도 잘림·겹침·가로 넘침이 없다 [캡처]. 예외는 이미 보고된 320 날짜 머리 말줄임(DES-3) 하나다.
- 아래 고칠 것 3건은 **모두 배포를 막지 않는다.** 1번(셰브런)은 접힌 캡처와 넓은 폭 md5 를 건드리지 않는 작은 수정이라 **같은 커밋에 넣기를 권한다.**

## ② 고칠 것 (우선순위순, 3건 — 배포 조건 아님)

### 1. 펼친 상태에서도 셰브런이 아래(`expand_more`)를 가리킨다 — 열림·닫힘을 모양으로 보일 것

- **현재 [캡처]:** `after-expanded-390-cond.png` 는 카드가 펼쳐져 셀렉트 여섯 개가 보이는 상태다. 그런데 머리 오른쪽 셰브런(약 x349, y105)이 접힌 상태(`after-390-cond.png` 약 x349, y107)와 **같은 모양**이다. `after-expanded-360-cond.png` 도 같다. **[코드]** `expand_more</span></summary>` 에 열림 상태를 반영하는 변형이 없다.
- **문제:**
  - UX-8 전에는 이 머리가 큰글씨에서만 보였다. 이제는 **조건을 건 폰 결과 화면 전부**의 손잡이다.
  - 펼친 뒤 "여기를 누르면 접힌다"는 신호가 없다. 아래 화살표는 "더 펼칠 것이 있다"로 읽힌다.
  - 앱 안에 이미 규칙이 있다. **[코드]** `detail.html`·`dashboard.html` 의 details 는 `group-open:rotate-90 transition` 으로 셰브런을 돌린다. 이 카드만 예외다.
- **목표:**
  - 셰브런 span 에 `group-open:rotate-180 motion-safe:transition-transform` 를 준다. details 에는 `group` 이 이미 붙어 있다. 모션 줄이기 설정이면 애니메이션 없이 바로 뒤집힌다.
  - **(선택)** 펼친 상태에서는 부제 `— 현대 외 3` 을 `group-open:hidden` 으로 숨긴다. 바로 아래 셀렉트가 같은 값을 보여 주므로, 펼친 머리는 `검색 · 필터 ⌃`(닫기 손잡이)면 충분하다. 펼침 비용 +28px 도 가벼워 보인다.
- **검증:** 접힌 캡처(폰·큰글씨)와 넓은 폭 캡처의 md5 는 **바뀌면 안 된다.** 바뀌었다면 규칙이 엉뚱한 곳에 걸린 것이다. 달라져야 하는 것은 `after-expanded-*` 2장뿐이다.
- 같은 모양의 `판정 표시 설명`(`#listLegend`) 셰브런도 열려도 돌지 않는다(기존). 같은 처방으로 함께 고치면 된다.

### 2. 접힌 머리의 `외 N` 이 정렬·페이지까지 센다 — 조건 수만 셀 것

- **현재 [캡처]:**
  - `after-360-date.png`: 머리는 `검색 · 필터 — 2026-09-01 매각 외 1` 이다. 바로 아래 해제 칩은 `2026-09-01 매각 ✕` **하나**뿐이고, 요약 줄은 `2026-09-01 매각 · 매각기일순 · 필터 초기화` 다. 즉 `외 1` 은 **정렬**이다.
  - `after-390-cond.png` 의 `현대 외 3` 도 셋 중 하나가 정렬이다(칩은 둘).
- **현재 [코드]:**
  - 머리는 `_cs.parts|length - 1` 로 센다. `_cs.parts` 에는 정렬 라벨과 `page ~ '/' ~ total_pages ~ '페이지'` 가 들어 있다. 그래서 같은 조건의 2페이지에서는 머리가 `현대 외 4` 로 바뀐다(캡처는 없고 코드로 확인).
  - 같은 파일의 `has_filter` 주석은 "정렬·페이지는 조건이 아니다(UX-7 판정)"라고 적는다. **한 파일 안에서 '조건'의 정의가 둘이다.**
- **문제:**
  - 라벨이 `검색 · 필터 —` 라서 `외 1` 은 "필터가 하나 더 걸려 있다"로 읽힌다.
  - 경매달력에서 날짜로 들어오면 URL 에 `sort=sale_date` 가 붙는다(캡처 URL `date=2026-09-01&sort=sale_date`). 그래서 이 경로로 들어온 폰 결과 화면은 **없는 필터를 하나 더 말하게 된다** [추정 — 모든 달력 링크를 확인하지는 않았다].
  - 데이터 신뢰가 1순위인 제품에서 "숨은 조건이 결과를 줄이고 있나?"라는 의심은 비싸다.
  - 원래 큰글씨에서만 보이던 것을 UX-8 이 폰 사용자 전체로 넓혔다.
- **목표:**
  - `외 N` 을 **조건 부품 수 − 1** 로 센다. 정렬과 페이지는 뺀다.
  - 방법: 정렬을 붙이기 직전의 `_cs.parts|length` 를 따로 기억해 둔다. 주행거리 부품 위치를 기억하는 `km_idx` 와 같은 방식이다.
  - 결과 예시: `— 현대 외 2`(아래 칩 두 개와 수가 맞는다), `— 2026-09-01 매각`(`외` 없음).
  - 요약 줄(`#condSummary`)은 전문 그대로 둔다. 정렬은 거기서 말하면 된다.
  - 덤으로, 320 일반 모드의 날짜 머리 잘림(`mid-b-320-date.png` 의 `— 2026-09-01 매각 …`, 147px 필요·143px 표시 [보고서 §3])이 날짜 하나만 건 경우에는 풀릴 것이다 [추정: `외 1` 이 빠지면 글자 폭이 약 20px 줄어든다. 재측정 필요].
- **범위:** 큰글씨 머리도 같은 문자열이라 큰글씨 캡처 md5 가 바뀐다. 그래서 UX-8 커밋이 아니라 **DES-3 과 묶은 별도 티켓**으로 처리한다. 테스트의 `— 현대 외 3` 단언은 `외 2` 로 바뀐다.

### 3. 접힌 상태에서 제조사·판정은 한 번에 뺄 수 없다 — 티켓 후보(측정 후 판단)

- **현재 [캡처]:** `after-390-cond.png` 에서 `현대` 는 머리(`— 현대 외 3`)와 요약 줄에만 있다. 접힌 칩 줄에는 `1,000~2,000만 ✕`·`2018년 이후 ✕` 뿐이다. **[코드]** `filter_chips` 매크로에는 제조사·판정 칩이 원래 없다. 펼친 카드에서는 셀렉트가 그 역할을 하기 때문이다.
- **문제:**
  - 가격대는 그대로 두고 제조사만 풀어 다른 브랜드를 보려는 경우를 보자. HEAD 는 셀렉트 → `전체 제조사` → [적용] 이었다. UX-8 이후 폰 결과 화면에서는 그 앞에 **펼치기 탭이 하나 더** 붙는다.
  - 제조사는 머리의 첫 부품이 되기 쉬운 축이다. (b) 가 가격대·연식에서는 "하나만 빼기 1탭"을 지켰지만, 가장 흔한 축에서는 지키지 못한다.
  - `필터 초기화` 는 1탭이지만 조건을 전부 푼다.
- **목표(제안, 설계 판단 필요):**
  - **접힌 줄(`filter_chips(false)` 경로)에만** `현대 ✕` 와 판정 해제 칩을 더한다. href 는 그 키만 뺀 쿼리로 한다(기존 `qs_no_*` 관례). 펼친 카드 안에는 넣지 않는다(셀렉트와 중복된다).
  - **대가:** 제조사만 건 결과 화면에도 줄이 생겨 34px 을 쓴다. 320 에서는 칩이 하나 늘어 셋째 칩부터 페이드 뒤로 간다.
  - UX-4 규칙(첫 ✕ 가 페이드 앞)은 `현대 ✕` 가 짧아 통과할 것이다 [추정].
  - **먼저 잴 것:** 320·360 에서 `maker+price+year` 조합의 첫 ✕ 우변, 그리고 제조사만 건 화면에서 첫 카드 가격 줄의 위치.

## ③ 잘된 점 (유지)

1. **번쩍임이 없다는 것을 공허하지 않게 증명했다.**
   - 기본 상태를 서버가 정하고(`open` 없이 렌더), 동기 스크립트는 details 바로 뒤에서 첫 페인트 전에 돈다.
   - 매 프레임 상태를 기록한 테스트(P5)를 뒀다 [보고서].
   - 스크립트를 `setTimeout 200` 으로 늦춘 변이체가 3건 실패로 잡혔다 [보고서 §5-1]. 테스트가 실제 결함을 잡는다는 증거다.
   - 스크롤 복원보다 먼저 돈다는 것도 테스트로 고정했다.
2. **⑤ 를 두 벌 만들어 캡처로 비교했고, (b) 는 HEAD 보다도 낫다.**
   - `before-320-cond.png` 는 카드 안 칩 행이 `[검색 저장][1,000~2,000만 ✕][2…` 이라 둘째 칩이 카드 끝에서 잘린다.
   - `after-320-cond.png` 는 접힌 줄에 `1,000~2,000만 ✕`·`2018년 이후 ✕` 가 둘 다 온전하다 [캡처].
   - 검색 저장(약 110px)이 앞에서 빠졌기 때문이다. 320 에서는 칩을 누르기가 HEAD 보다 쉬워졌다.
3. **무변경을 정직하게 증명했다.**
   - HEAD 자체가 넓은 폭에서 md5 가 갈린다는 것(래스터 비결정성)을 5회 대조군으로 드러냈다.
   - 768-plain 예외도 숨기지 않았다 [보고서 §4].
   - 눈으로 봐도 768·1440a·큰글씨 before/after 가 같다 [캡처].
4. **히트영역을 레이아웃에 손대지 않고 넓혔다.**
   - `::before` 로 접힘 56px·펼침 44px 을 확보했다. 펼친 상태에서는 아래로 넓히지 않아 바로 밑 셀렉트의 탭을 뺏지 않는다 [보고서 §1].
   - 큰글씨 md5 가 같다는 것이 픽셀 불변의 증거다.
5. **칩 마크업이 한 벌이다.**
   - 매크로 하나에서 두 번 부르고, 매크로 전과 바이트 단위로 같다는 것을 11개 URL 로 비교했다 [보고서].
   - 접힌 줄의 칩은 펼친 카드 칩과 같은 연보라 톤이라 "지금 걸린 조건"이라는 의미가 흔들리지 않는다 [캡처].

## ④ 질문 답

### (1) ⑤ 에서 고른 안(b) 이 맞는가 — **맞다.**

- **비용은 34px(283px 중 12%)이다** [보고서 §2]. 그런데 이 34px 은 첫 화면이 보여 주는 판단 재료를 바꾸지 않는다.
  - 390 에서 첫 카드 가격 줄은 (a) 580, (b) 614 로 둘 다 탭바(787) 위다 [보고서].
  - `mid-a-360-cond.png` 와 `mid-b-360-cond.png` 모두 첫 카드가 기일 줄까지 다 보인다(약 y610 / y645). 차이는 둘째 카드가 얼마나 보이느냐뿐이다. (a) 는 사진과 `2023년식 32,032km 외관손상` 줄까지 보이고, (b) 는 사진 윗부분만 보인다 [캡처].
- **이득은 두 가지다.**
  - 조건 하나 빼기를 1탭으로 지켰다(UX-1). (a) 는 2탭이고, ✕ 가 가로 스크롤 뒤에 있으면 스와이프가 더 든다 [보고서].
  - 320 에서는 HEAD 보다 칩이 더 잘 보인다(잘된 점 2).
- **묶여 보이는 모양도 맞다.** 칩 줄이 카드 바로 아래 약 10px, 차종 행 위 약 27px 에 있다. 가까운 쪽인 카드의 조건으로 읽히고, 차종 같은 또 하나의 프리셋 줄로 읽히지 않는다 [캡처 `after-390-cond.png`].
- **큰글씨에서 줄을 숨긴 판단도 지금은 맞다.** `after-large-360-cond.png` 에서는 첫 카드 가격이 이미 폴드 밖이다(사진 하단 약 y700, 제목 약 y737) [캡처]. 큰 글씨 칩 줄(약 40px)을 더하면 더 나빠진다.
- 남는 손실은 제조사·판정이다(고칠 것 3).

### (2) 접힌 머리가 '누르면 펼쳐진다'로 읽히는가 — **접힌 상태는 읽힌다. 펼친 상태가 문제다(고칠 것 1).**

- **접힌 상태 [캡처 `after-390-cond.png`·`after-360-cond.png`]:**
  - 펼친 카드와 같은 테두리·그림자의 카드 한 줄이라, 같은 물건이 접혀 있다는 연속성이 있다.
  - 구성은 `filter_list` 아이콘 + 굵은 `검색 · 필터` + mut 톤 부제 + 오른쪽 끝 셰브런이다. 흔한 아코디언 문법이다.
  - 부제의 mut 톤은 부속 정보로 읽혀서 맞다. 탭 영역 56px 도 충분하다 [보고서].
  - `펼치기` 같은 글자를 더하는 것은 반대한다. 폭을 먹어 DES-3 잘림을 키운다.
- **펼친 상태:** 셰브런이 그대로라서 "누르면 접힌다"가 읽히지 않는다. 고칠 것 1 의 회전 하나로 해결된다.

### (3) 펼침 기억(같은 조합 안) 규칙이 예측 가능한가 — **예측 가능하다. 예외는 하나다.**

- **규칙은 사용자가 배울 필요가 없는 한 문장으로 줄어든다.** "조건을 바꾸면 결과를 보여 준다(접힘). 같은 조건으로 넘겨 보는 동안에는 내가 둔 대로다."
  - 사용자가 탭했을 때만 기억한다 [코드 `nc:listFilterOpen` 스크립트의 `user` 플래그]. 큰글씨 토글이나 폭 변화가 연 것은 기억하지 않는다.
  - 아무것도 바꾸지 않고 [적용]하면 펼친 채 남는다(P3). "바뀐 게 없다"는 느낌과 맞는다.
  - 펼친 카드 안에서 칩 ✕ 를 누르면 접힌다. 셀렉트를 바꾸고 [적용]한 경우와 같은 결과라 일관된다.
  - sessionStorage 라서 새 세션은 접힘으로 시작한다. 결과 화면의 기본 상태로 적절하다.
- **예외:** 큰글씨를 끄면 `ncToggleLarge()` 가 `f.open=!on` 으로 조건·기억과 상관없이 카드를 편다 [코드]. 드물고 다음 로드부터는 규칙대로라, 티켓 없이 알고만 있으면 된다(보고서 §6-5 에 동의).

### (4) 폰만 접고 넓은 폭은 펼친 채 두는 판단에 동의하는가 — **동의한다.**

- **768:** 필터 카드 하단이 266, 첫 카드 가격 `14,000,000` 이 약 y699 로 탭바(약 843) 위다 [캡처 `after-768-cond.png`]. 이미 판단 재료가 첫 화면에 있으니 접어서 얻을 것이 없다. 해제 ✕ 도 카드 안 한 줄에 다 보인다.
- **1440 관리자:** 표 레이아웃이고 필터는 두 줄이다 [캡처 `after-1440a-cond.png`].
- **1440 공개(420 폰 프레임)가 접히는 것:** 동의한다. 프레임은 폰 화면의 미리보기다. 폰과 다르게 그리면 PC 방문자는 폰 사용자가 보지 못하는 화면을 보게 된다 [캡처 `after-1440-cond.png` = 폰과 같은 구성]. `window.self !== window.top` 분기를 넣지 않은 판단도 맞다.

### (5) 조건 요약 줄과 접힌 머리가 같은 말을 두 번 하는가 — **글자는 겹치지만 하는 일은 다르다. 셋 다 둔다.**

- 접힌 상태 390 첫 화면에서 `현대`·`1,000~2,000만`·`2018년 이후` 는 각각 두 번씩 보인다 [캡처 `after-390-cond.png`: 머리 y≈107 · 칩 y≈155 · 요약 줄 y≈249].
- 그래도 셋은 **서로 대신할 수 없는 일**을 한다.
  - **머리:** 카드를 여닫는 유일한 손잡이이고, "안에 무엇이 있는지"를 한 조각으로 말한다.
  - **칩 줄:** 조건을 하나씩 빼는 유일한 1탭 경로다.
  - **요약 줄:** 정렬, `(주행거리 미상 N건 제외)` 라는 데이터 손실 고지, 폰의 `필터 초기화` 를 가진 **유일한 자리**다. 데이터 신뢰 장치라서 빼면 안 된다.
- 고칠 것은 겹침이 아니라 **머리가 조건 수를 틀리게 말하는 것**이다(고칠 것 2). `현대 외 2` + 칩 둘이 되면 머리와 칩이 서로를 확인해 주는 관계가 된다.
- 펼친 상태의 겹침(머리 부제와 바로 아래 셀렉트)은 고칠 것 1 의 선택 항목(`group-open:hidden`)으로 없앤다.

## 확인 필요(추측) — 근거를 대지 못한 것만

- **320×568 같은 작은 폰:** 측정은 844 높이뿐이었다. 첫 카드 top 373.5 + 카드 구조로 보면 가격 줄은 (a)·(b) 모두 탭바 아래일 것이다 [추정]. (a)/(b) 판정을 뒤집지는 않지만 캡처로는 확인하지 못했다.
- **폰 가로(폭 ≥ 640, 높이 약 390):** 규칙대로 카드가 펼쳐진다(P8). 이때 첫 카드가 첫 화면에 보이는지는 캡처가 없다.
- **검색 저장이 한 탭 더 깊어진 영향**(보고서 §6-3): 저장은 기기 로컬(localStorage)이라 서버에서 사용량을 셀 수단이 있는지부터 확인해야 한다. 재방문 장치라 지켜볼 가치가 있다.
- **2페이지 머리 `현대 외 4`:** 코드로만 확인했고 캡처는 없다(고칠 것 2).
- **TWA 실기기:** 헤드리스 `is_mobile`·`has_touch` 까지만 확인됐다. 실제 안드로이드 Chrome 에서 details 토글과 탭 영역은 미확인이다.
- **768-cond `b3e748c1`:** 1회 관측된 값이다. 래스터 비결정성이라는 보고서 추정에 이의는 없지만 검증도 하지 않았다.
