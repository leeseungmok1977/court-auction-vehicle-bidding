## 4. 관찰 (결함 아님, 판단 참고)
- **잠재 — SQL 조각 ↔ 파이썬 술어의 타입 불일치**(tmp DB 로 재현, 사본에는 해당 행 0): `year` 가 숫자 아닌 TEXT(`'2018년'`)면 SQLite 는 TEXT > INTEGER 라 `year >= ?` 가 **모든 하한에서 참**이고 파이썬 `_as_int` 는 None(제외) — SQL 경로와 파이썬 경로(segment 등)의 총수가 갈린다. `mileage_km` REAL `100000.5` 는 SQL `<= 100000` 거짓·파이썬 `int()` 100000 참. TEXT `'12만'` 은 SQL 에서 미상도 20만 이하도 아니고 파이썬은 미상. 열 친화도가 INTEGER 라 숫자 문자열(`"2018"`·`"120000"`)은 저장 시 정수로 바뀌고(확인), 파서 `_to_int` 가 막고 있어 **지금 도달 경로는 없다**(backend §5-4 와 같은 판단). 후속 티켓 후보: SQL 조각에 `typeof(year)='integer'` 가드 또는 파이썬 `_as_int` 를 SQL 의 수치 비교와 같게(REAL 은 내림 아님).
- **누적 라벨 `(N)`**(backend §5-2·frontend §7-2): `2015년 이후 (1035)` 옆 `2018년 이후 (746)` — 구간으로 읽힐 위험은 디자인 판정 몫. 숫자 자체는 ⑦ 단조성으로 고정.
- 미상 문구는 `km_max` 를 골랐어도 **미상 0건이면 그리지 않는다**(frontend §6-4 판정 요청) — 서버 계약 §2.3 의 논리와 일관되고, 테스트 ⑤ 가 그 규칙을 고정했다. 판정이 바뀌면 그 테스트 한 줄을 바꾼다.
- 성능(4 스레드 동시 부하, 단독 시간 미측정): 가장 느린 셀 `none` 7.0s, 5초 초과 19/550(전부 `none`·`picks`·`all`). FEAT-1 QA 때 usepick 20.4s 였던 것이 이번엔 최대 5.0s — 같은 조건이 아니라 비교하지 않는다(추정: 그때는 캡처와 겹쳤다).
- 사본 `all=1&year_min=2015&km_max=200000` 미상 174, `none` 76 — 라이브 입찰예정 425건 기준 스펙의 60 과 다른 모수(전체 vs 입찰예정)라 비교 대상이 아니다.
