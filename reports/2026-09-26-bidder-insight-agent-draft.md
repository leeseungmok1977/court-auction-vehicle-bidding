# 신규 에이전트 초안 — `bidder-insight` (경매 참여자 심리·관심사 조사)

- 상태: **초안 — 오너 승인 전.** 승인되면 `.claude/agents/bidder-insight.md` 로 옮기고 `docs/ORG.md` 성장부에 등록한다(조직 구조 변경 = 오너 승인 항목).
- 출처: 오너가 가져온 설계(분석 프레임 6범주·소스·4역할 구조·분류 JSON)를 이 조직의 규칙(C.4·준법·보고 형식)에 맞게 손본 것. 실측은 2026-09-26 Steward.

## 1. 실측 — 지금 이 환경에서 되는 것
| 소스 | 도구 | 결과 | 비고 |
|---|---|---|---|
| 웹 검색(키워드) | WebSearch | **됨** — 클리앙·블라인드·태인 칼럼·개인 블로그·정보 사이트가 검색됨 | 미국 기반 검색이라 네이버 결과는 약함 |
| 클리앙 게시글+댓글 | WebFetch | **됨** — 본문과 댓글 13개 요약 읽힘 | |
| 블라인드 게시글 | WebFetch | **됨** — 로그인 없이 본문·댓글 읽힘 | 민감 소스 — 준법 검토 대상 |
| 뽐뿌 검색·게시글 | WebFetch | **됨** — 검색 결과 읽히나 잡음 큼 | 키워드 정교화 필요 |
| 네이버 지식iN·블로그·카페 | WebFetch | **안 됨** — 도구가 네이버 도메인을 못 가져옴 | 약관상 자동수집 제한도 있어 **제외** |

| **정량(우리 DB)** | Bash(sqlite ro) | 낙찰가·감정가·최저가·유찰횟수·시세·낙찰가율 **있음** (live `sale_results` 290건) | **응찰자 수는 법원이 공개하지 않아 없음** — "입찰자 수 vs 낙찰가율" 검증은 불가, "유찰횟수·감정가 대비 vs 낙찰가율"은 가능 |

## 2. 역할과 자리
- 부서: **성장부**(`growth`·`voice` 옆). 고객의 소리(`voice`)가 *우리 사용자*의 말을 듣는 자리라면, `bidder-insight` 는 *아직 우리 사용자가 아닌 경매 참여자*의 말을 듣는 자리다.
- 부르는 때: 기능 우선순위·무료/유료 경계·문구를 정할 때, 월 1회 정기(월간 보고 앞), 신규 기능 기획 전.
- 권한: 조사·분류·보고만. 코드 수정 없음, 외부 게시 없음, 비용 집행 없음(WebSearch/WebFetch 는 추가 비용 없음).

## 3. 정의 파일 초안 (`.claude/agents/bidder-insight.md`)
```
---
name: bidder-insight
description: 경매 참여자 조사. 공개 커뮤니티의 경매 글·댓글을 심리 6범주·관심 주제·참여 단계·미충족 니즈로 분류해 "심리 → 불편 → 기능 제안"으로 정리한다. 원문 인용·닉네임 저장 금지, 네이버 도메인 제외, 요청 전 5~10초 대기. 코드는 수정하지 않는다.
tools: Read, WebSearch, WebFetch, Write, Bash, Grep, Glob
model: sonnet
---
```
본문 핵심(요지):
- 분석 프레임 6범주: 기회추구 · 불확실성불안 · 경쟁과열 · 손실회피 · 사회적증거 · 통제감. 관심 주제: 가격 · 차량상태 · 입찰절차 · 인도·명도 · 세금·서류 · 기타. 단계: 탐색 · 입찰준비 · 입찰 · 낙찰후 · 패찰후.
- 글 하나당 출력 JSON(오너 초안 채택): `psychology[]`, `concern_topics[]`, `stage`, `sentiment(-2~2)`, `key_quote_summary(≤30자, 원문 인용 금지)`, `unmet_need|null`, 광고·홍보는 `{"skip": true}`. **근거 없는 범주는 붙이지 않는다.**
- 저장하는 것: 분류 JSON + 소스명 + URL + 게시일. **저장하지 않는 것**: 원문, 닉네임·프로필, 회사명 등 식별 요소.
- 소스 규칙: 허용 목록만(준법 검토 통과분). 소스당 1회 실행 30건 상한, 요청 전 5~10초, 403/429/캡차 시 즉시 중단.
- 보고: `reports/bidder-insight-YYYY-MM-DD.md` — [모집단(몇 건·어디서·언제)] → [범주별 빈도·단계별 분포] → [미충족 니즈 상위 5] → [우리 DB 정량 교차(유찰횟수·감정가 대비 vs 낙찰가율)] → [기능 제안: 무료/유료 경계 근거]. 사실/추정 구분.

## 4. 실행 구조 — 4역할은 워크플로 단계로
에이전트 파일은 하나, 실행은 Workflow 로 4단계: **수집**(키워드×소스 fan-out, WebSearch→WebFetch) → **분류**(글마다 구조화 JSON, 스키마 강제) → **분석**(집계 + `data/auction.db` mode=ro 교차) → **리포트**. 검증 단계(`qa-engineer`)가 표본 재분류로 분류 일관성을 반박한다(같은 글을 두 번 분류해 범주 일치율).

## 5. 파일럿 제안 (승인 시 첫 실행)
- 범위: 클리앙·블라인드·뽐뿌 + 검색으로 잡히는 개인 블로그, 키워드 6개("법원경매 자동차 후기" "법원경매 차 처음" "경매 낙찰 후회" "자동차 경매 입찰가" "경매 차 인수" "경매차 침수"), **총 40~60건**.
- 산출: 첫 리포트 1건 + 분류 일치율. 이걸로 범주·키워드를 고친 뒤 정기화.
- 필요한 결정: ① 에이전트 추가 승인 ② 유튜브 API 키(선택) ③ 블라인드 포함 여부(준법 검토 결과에 따라).
