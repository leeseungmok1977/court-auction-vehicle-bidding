## ② 8장 캐러셀 리듬 — 튀는 장은 **10 이지 06 이 아니다**
- 크기: 9장 전부 51px. 위치: 1줄 7장 동일, 06 만 2줄이라 1→2번 장에서 **한 번** 튀는데 "1번 장이 헤드라인"으로 읽혀 자연스럽다.
- **10_report_lower 는 깬다**: 캡션 잉크 951px(x≈64~1016), 카드 x 70~1009 → **캡션이 카드보다 좌우 각 ≈6px 넓다.** 8장 중 유일하게 띠 글자가 카드 좌우선 밖으로 나간다. → ④-1

## ③ 기준월 자리 — **권고: B1(캡션 아래 가운데) 유지.** 선택은 오너 몫.
1. 기준월의 기능은 면책("그때는 참이었다")이고 시선이 닿아야 한다. 1/4 에서 우하단 스탬프는 캡션 밑보다 눈에 훨씬 덜 들어온다.
2. **B1s 스탬프가 앱 크롬으로 오독될 자리에 앉는다** — 카드 헤더 우측 아이콘 열과 같은 x 대역, 안드로이드 상태바가 시계·배터리를 두는 관습과 같은 자리. 1차에서 안 A 캡슐을 탈락시킨 이유와 같은 계열.
3. 1차에서 우려한 "부제로 붙어 읽힘"은 실물에서 약하다 — 51 Bold 흰 / 32 Medium 크림의 위계가 분명하다. 설령 붙어 읽혀도 의미가 틀리지 않는다.
4. B1s 채택 시 8장 재생성 + 06(2줄) 재검수 필요(④-2).
- B1s 의 장점 하나: 기준월 위치가 8장 공통이 된다(B1 은 06 만 다르다).

## ④ 새로 생긴 문제 — 확정 1건, 추정 1건
**④-1 (확정) `10_report_lower` 캡션이 카드 폭을 넘는다 — 2차 변경으로 새로 생긴 것**
- 캡션 폭 상한이 `CAPTION_SIDE_MARGIN = 56` → **968px 로 카드 폭과 무관하게 고정**. 1차는 카드 956·캡션 최대 950 이라 우연히 카드 안이었다. 2차에서 띠 250 → 카드 939 로 좁아졌는데 상한은 968 그대로, 캡션은 Pretendard 로 951 → **카드 밖 6px**. (1차에서 카드 939·gutter 70 을 비용으로 적은 건 검수자 본인인데 캡션 상한 연동을 말하지 않았다 — 검수자 누락이기도 하다.)
- 목표: 캡션 폭 상한을 **카드 폭 이하로 연동**. `uniform_caption_size` 는 **50px** 로 1 내려갈 것(추정: 951×50/51 ≈ 932 < 939). 06 은 여전히 2줄. 8장 재생성 후 1/4 재확인. 10 을 `·` 앞에서 2줄로 나누는 안은 문구 분절이라 권하지 않음.

**④-2 (추정) B1s 를 06 에 적용하면 2줄 캡션과 스탬프가 근접**한다 — x 대역 12px 겹침, 세로 ≈19px. B1 유지면 해당 없음.

## ⑤ 제출 가능 여부 — **조건부 가능**
- **필수**: 06 대시→줄바꿈 **오너 승인 기록**. 승인 시 콘솔 alt text 는 확정본(대시 포함)으로 넣되 "그림은 줄바꿈"을 표에 각주로.
- **권고(비용 = 상수 하나 + 재실행)**: ④-1 캡션 상한을 카드 폭에 연동해 8장 재생성. 차단 사유는 아니다(Play 실표시에서 6px 가 보일지 미확인).
- 재검수는 ④-1 반영본의 10 한 장 + 컨택트시트만.

## 잘하고 있는 것
1. Pretendard 로 띠가 앱의 일부가 됐다. 리포 woff2 변환으로 새 바이너리를 들이지 않은 처리도 옳다.
2. 250px 띠의 71/71·38/39 여백과 r=28 카드 — 1/4 에서도 카드가 테두리로 읽힌다.
3. 세트 공통 51px 을 10 에 못 박고 나머지를 키우지 않은 판단.
4. B1s 를 실제 렌더로 만들어 준 것 — "오너 선택"을 근거 있는 권고로 바꿀 수 있었다.

## 확인 필요(참고)
- Play 캐러셀 실표시 크기 미확인.
- `08_detail_lower` 상단에 "매각 장소" 행이 반 가려진 채 보인다 — 원본 스크롤 위치이지 오버레이 탓 아님. 07→08 연속 스크롤을 보여 주는 효과도 있어 판단 보류.
- 09·10 리포트 장은 탭바가 없어 카드가 흰 본문으로 화면 밑까지 흐른다 — 앱 구조.
