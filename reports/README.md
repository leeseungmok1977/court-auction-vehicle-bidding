# reports/ — 에이전트 보고서 (부서 간 유일한 통로)

서브에이전트는 **서로 직접 대화하지 못한다.** 부모 세션의 대화도 보지 못한다.
그래서 협업은 이렇게 한다.

```
Steward(메인 세션)
   │ ① [작업 지시서]로 지시
   ▼
insight / growth / voice / …      ② 결과를 이 폴더에 파일로 남긴다
   │
   ▼
Steward  ③ 읽고 검증한 뒤, 다음 담당에게 "그 파일을 읽어라"고 지시해 연결
```

## 머리말 — 다음 담당을 적는다 (2026-09-26)

모든 보고서는 **맨 첫 줄부터** [`.claude/agents/_handoff-protocol.md`](../.claude/agents/_handoff-protocol.md)
형식의 YAML 머리말로 시작한다. `handoff:` 에 적은 담당에게 순환계가 지시서(`orders/`)를 만든다 —
③의 "다음 담당에게 읽으라고 지시해 연결"을 Steward 기억 대신 이 한 줄이 맡는다.
머리말이 없는 옛 보고서는 순환계가 건너뛴다(고치지 않는다 — 이미 끝난 기록이다).

## 파일 이름

```
YYYY-MM-DD-담당-주제.md        예) 2026-09-23-insight-이탈원인.md
```

## 규칙

1. **Steward만 오너에게 보고한다.** 이 폴더의 문서는 조직 내부 산출물이다.
2. **사실과 추정을 구분해 적는다.** 섞여 있으면 Steward가 구분을 요구한다.
3. **출처와 조건을 밝힌다** — 어떤 데이터를, 어느 기간에, 어떤 조건(봇·폴링·관리자 제외 여부)으로.
4. **개인정보를 옮기지 않는다.** 리뷰 속 연락처·계정은 요약에서 제외한다.
5. 서버 주소·키 경로를 쓰지 않는다. 이 폴더는 저장소에 커밋된다.

## 왜 파일로 주고받나

메모리에 담아 넘기면 어느 판단이 어느 근거에서 나왔는지 나중에 되짚을 수 없다.
2026-09-22에 마케팅 진단 3건이 거짓으로 드러났을 때, **파일로 남아 있었기 때문에**
어디서 틀렸는지 찾아낼 수 있었다. 보고서는 검증 대상이지 통보가 아니다.
