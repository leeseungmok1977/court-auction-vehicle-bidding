## 2. 칩 판정 순서 — `schedState`

심각도 높은 것부터 본다. 결재함과 겹치는 행은 ③ 뿐이다.

| 순서 | 조건 | 칩 | 행 |
|---|---|---|---|
| ① | 실행된 적 없음 · 예정 없음 | 빨강 `실행된 적 없음 · 예정도 없음` | bad |
| ② | 돈 적 있고 결과 ≠ 0 | 빨강 `실패 · 결과 N` | bad |
| ③ | `silence.bad` | 주황 = 라벨 머리(`조용히 안 돎`·`첫 실행 없음`). 칩 아래 사유 = 나머지(`마지막 성공 …`·`등록 … 뒤 …`) | late |
| ④ | 실행된 적 없음 · 예정 있음 | 주황 `아직 때가 안 됨`(전과 같다) | late |
| ⑤ | 실행 중 | 주황 `실행 중`(전과 같다) | — |
| ⑥ | `silence` 가 null(판정을 못 붙임) 또는 `silence.warn`(트리거를 못 읽음·§1 한도 없음) | `확인 불가`(mute). 사유 줄 = "결과 0 · 조용히 안 도는지 판정 못함 · 사유는 맨 위 '읽지 못한 것'" | — |
| ⑦ | 그 밖 | 초록 `정상` | — |

- ②를 ③보다 먼저 본다. 순환계는 실패 행에 `bad` 를 싣지 않지만, 둘이 함께 와도 빨강이 주황으로 내려가지 않게 했다(테스트로 고정).
- ③을 ④보다 먼저 본다. 전에는 '첫 실행 없음' 작업이 '아직 때가 안 됨'으로 그려졌다(backend §8 권고와 같다).
- ⑥은 backend §8 "null — '정상'으로 그리지 말 것"과 이 화면의 원칙 "정상 < 확인 불가 < 이상 < 멈춤"을 따른 것이다.
  - ⚠ 지시서는 ⑥을 이름으로 들지 않았다. 판정을 따르게 하는 일의 일부로 읽었다. 되돌리려면 ⑥ 한 줄을 지우면 된다.
- 라벨이 비어 있는데 `bad` 면 칩은 `예약 작업 경보`(RSN.task)다. 빈 칩을 그리지 않는다.

### 타일 — `schedTile`

- **색**: 실패·실행된 적 없음이면 빨강(전과 같다). 아니고 `sched_silent > 0` 이면 주황. 아니고 확인 불가 행이 있거나 `sched_silent` 가 null 이면 mute. 모두 아니면 무채색.
- **부제**: 볼 것을 가리지 않고 모두 적는다(전에는 가장 심한 하나만 적었다). 예: `1개 실패 · 2개 조용히 안 돎 · 1개 첫 실행 없음 · 1개 확인 불가`.
  - 경보 낱말은 표의 칩 글자다. '첫 실행 없음'을 '조용히 안 돎'으로 뭉뚱그리지 않는다. 서버 `sched_silent` 는 둘을 합친 수라서 칩 글자별로 나눠 센다(합은 같다 — 테스트).
  - 항목마다 nowrap 이다. 1440px 에서 '확인 / 불가'로 낱말이 홀로 떨어졌다(heartbeatTile 의 `nw` 와 같은 처방).
- 목록이 비면 `예약 작업을 읽지 못했다`(mute)다. 전에는 '0개 · 정상'이었다 — 표는 같은 순간 "예약 작업을 읽지 못했다"라고 말했다.
- 볼 것이 없고 첫 실행 대기가 있으면 `N개는 첫 실행 대기(예정일 있음)`(전과 같다). `sched_pending` 에서 첫 실행 없음이 빠진 새 뜻은 서버 몫이다.
