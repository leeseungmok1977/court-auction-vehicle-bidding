## 2. 좁은 폭 그리드 처리와 이유

폼은 `<div class="grid grid-cols-2 gap-2 w-full sm:contents">` 안에 셀렉트 3개 + [적용]이 2×2 를 채우고 있었다. 셀렉트가 넷이 되면 다섯 항목이라 어떤 배치든 하나는 혼자 남는다.

| 시도 | 배치(좁은 폭) | 측정 | 눈으로 본 것 | 판정 |
|---|---|---|---|---|
| 1차 | [판정][제조사] / [가격대][정렬] / **[적용 전폭]** | 빈 셀 없음·넘침 없음 통과 | **360px 캡처에서 `1,000~2,000만 (41` — 건수가 잘림**(반 칸 147px; 320px 은 127px 라 더 잘림) | 폐기 |
| 최종 | [판정][제조사] / **[가격대 전폭]** / [정렬][적용] | 빈 셀 없음·넘침 없음, 320~430 전부 전체 라벨 보임 | 320·360·390 캡처에서 `1,000~2,000만 (418)` 온전 | 채택 |

- 왜 패딩 축소가 아니라 전폭인가: 320px 반 칸 127px − 화살표 영역 ≈20px − 패딩 8px(축소해도) ≈ 99px < 라벨 폭 ≈120px — 그래도 잘린다. 숫자가 잘려 보이는 것은 없는 것보다 나쁘다(사용자가 `41` 로 읽는다).
- 왜 건수를 빼지 않았나: 승인 스펙(`docs/backlog.md` FEAT-1: "셀렉트 옵션에 구간별 건수 `(144)`").
- [적용]은 원래 자리(정렬 옆 반 칸, 127~182px × 42px)로 돌아가 **기존 디자인에서 벗어난 것이 가격대 셀렉트 한 줄뿐**이다.
- sm 이상: 래퍼가 `sm:contents` 라 `col-span-2` 는 의미를 잃고 원래 flex 흐름(판정·제조사·가격대·정렬·검색창·적용)이다. 근거: 1440 캡처 md5 가 1차·최종에서 **동일**(`1469864b…`·`341e0c55…`) — 넓은 폭 렌더는 한 픽셀도 안 바뀌었다.
- 남는 비대칭(반 칸 셀렉트 사이에 전폭 셀렉트 하나)은 §6 에서 디자인 검수에 묻는다.

## 3. 측정표 (6폭 × 2URL, 최종 배치)

URL A = `/vehicles?price=1000-2000` (사본에서 총 418건) · URL B = `/vehicles?maker=현대&price=3000-` (52건). 값은 두 URL 이 같으면 한 번만 적었다.

| 폭 | 가로 스크롤 (`scrollWidth>innerWidth`) | 뷰포트 밖 요소(설계 외) | 설계상 뷰포트 밖 | 그리드 행 구성 (w×h) | 빈 셀 | 가격대 셀렉트 w×h | 해제 칩 w×h · 화면 안 |
|---|---|---|---|---|---|---|---|
| 320 | 없음(320) | 0 | 33 — 전부 오프캔버스 `aside`(`-translate-x-full`, lg 미만) 자손 | [판정 127×36][제조사 127×36] / [가격대 262×36] / [정렬 127×42][적용 127×42] | 없음 | 262×36 | A 117×26 · B 88×26 · 안 |
| 360 | 없음 | 0 | 32 (aside) | 147 / 302 / 147+147 | 없음 | 302×36 | 안 |
| 390 | 없음 | 0 | 31 (aside) | 162 / 332 / 162+162 | 없음 | 332×36 | 안 |
| 430 | 없음 | 0 | 30 (aside) | 182 / 372 / 182+182 | 없음 | 372×36 | 안 |
| 768 | 없음 | 0 | 27 (aside — 768 도 lg 미만) | 그리드 `contents`(flex 흐름) | 해당 없음 | 176×36 (B 174) | 안 |
| 1440 | 없음 | 0 | 0 | `contents` | 해당 없음 | 176×36 (B 174) | 안 |

- 셀렉트 높이 36px(`.inp py-1.5`, 바꾸지 않음). [적용] 42px(히트영역 ≥40 충족). **정렬 셀렉트만 42px** — [적용]과 같은 그리드 줄이라 `align-items: stretch` 로 버튼 높이에 맞춰진다(확인된 사실: 최종 배치 측정값). 이 짝은 내가 만든 것이 아니다 — 변경 전 DOM 순서(판정·제조사·정렬·적용)에서도 2행이 [정렬][적용]이었으므로 같은 현상이 있었을 것이다(**추정** — 변경 전 상태를 되돌려 재지 않았다). 1차 시도([적용] 전폭)에서는 정렬이 36px 이었다(측정값).
- 칩 높이 26px — 이 줄의 기존 칩 전부와 같다(관례 준수). 40px 히트영역 기준에는 못 미친다 → §6.
- ③ 앵커 점프·고정 요소 가림: 이 변경은 앵커·고정 바를 만들거나 옮기지 않아 **해당 없음**(측정 안 함).
- "설계상 뷰포트 밖" 은 측정 스크립트가 `aside`·`.nc-chiprow`·`#rlb` 자손을 따로 센 것이다. 좁은 폭 칩 줄(`nc-chiprow`)은 가로 스크롤 + 우측 페이드가 설계이며, 가격대 칩 자체는 전 폭에서 화면 안(`left 148`)이다. 그 옆 `입찰예정 30일만` 칩이 페이드에 걸리는 것은 기존과 같다.
- 큰글씨(nc-large) 모드는 측정하지 않았다(§6).

측정 스크립트: scratchpad `measure.py`(Playwright, 6폭 × 2URL, `getBoundingClientRect` 기반) · 결과 JSON `feat1_measure2.json`. 재현: `serve.py`(사본 DB) 띄운 뒤 `PYTHONIOENCODING=utf-8 python measure.py`.

## 6. 못 한 것 · 디자인 검수에 물을 것

1. **어휘 불일치(확인된 사실, 백엔드 §5-2 그대로)**: 셀렉트·칩은 `~500만`·`3,000만~`(최저매각가 축), 같은 화면 카드의 정확도 층은 `500만 이하`·`2,000만 이상`(시세 축). 지시대로 바꾸지 않았다. **질문**: 한 화면에 두 어휘를 둘 것인가, `PRICE_BANDS` 의 label 한 곳을 층 어휘(`500만 이하`… 단 축이 다르다)에 맞출 것인가.
2. **전폭 셀렉트 하나의 비대칭(§2)**: 반 칸 셀렉트 사이에 전폭 하나. 대안은 (a) 좁은 폭에서만 건수 생략(스펙 위반) (b) 라벨 축약(단일 원천이라 서버 label 변경) (c) 지금 배치. **질문**: (c) 로 가도 되는가.
3. **칩 히트영역 26px**: 이 줄의 모든 칩이 26px 이라 관례를 따랐다. 40px 기준에 맞추려면 칩 전부를 같이 올려야 한다 → 별도 티켓 권고. 이 작업에서는 바꾸지 않았다.
4. 건수는 `{{ b.count }}` 그대로(천 단위 구분 없음). 사본 최대 418 이라 지금은 문제없지만 4자리가 되면 `(1163)` 로 찍힌다 — 스펙 표기 `(144)` 를 따랐다. **질문**: 4자리 대비 포맷이 필요한가(돈이 아니라 건수라 `|won`·`|man` 은 부적절).
5. `가격대 전체` 옵션에는 총수를 안 붙였다(이웃 `전체 판정`·`전체 제조사` 도 없음). 
6. **측정 안 한 것**: 큰글씨(nc-large) 모드(필터 카드가 접히고 셀렉트 한 줄이 늘어난다 — 폴드 영향은 **추정** 미미), 실기기, 라이브. 앵커 점프는 해당 없음.
7. 빈 결과 카드 `or price` 는 지시서 C 의 문자 밖(§1). 되돌리려면 그 한 토큰과 테스트 1건.
8. 셀렉트 `onchange` 자동 제출은 넣지 않았다(백엔드 보고의 예시는 `location.href` 방식이었지만 기존 셀렉트 3개가 전부 [적용] 제출이라 관례를 따랐다).

- **확인된 사실**: §1 의 변경 내용(diff), §3 측정값(스크립트 출력), §4 md5(`md5sum`), §5 테스트 수·시간(pytest 출력), 1차 시도의 `(41` 잘림(캡처를 Read 로 봄), 1440 md5 1차·최종 동일, 운영 DB 쓰기 없음(backup API 로 사본 생성, 앱은 `db.DB_PATH` 를 사본으로 바꿔 기동), 8765 무접촉.
