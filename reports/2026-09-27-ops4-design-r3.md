### #1 결재함 목적 줄이 140자에서 잘림(backend) → **해소**

**원문 목표**
- "목적 줄 첫 줄은 silence 라벨을 **그대로** 앞에 둔다 … 그 뒤에는 라벨에 없는 것만 붙인다."
- 조용히 안 돎: "`예약 작업 {name} — {label} · 다음 실행 {next}` — 괄호를 지운다."
- 첫 실행 없음: "`… — {label} · 다음 실행 {next}` — 1999 날짜를 쓰지 않는다."
- 실패: "`… — {label} · 마지막 실행 {last} 뒤 {h}시간` — 라벨에 '다음 실행 없음'이 있으면 반복하지 않는다."

- 확인 방법: "조용한 누락 픽스처로 결재함 1440·320 을 한 장씩 찍는다."

**지금** — after-inbox-1440·320·390 캡처와 measure JSON `ord.pp` 로 봤다. 6개 폭 모두 글자가 같다.

- standup: "예약 작업 naechaget-org-standup — 조용히 안 돎 · 마지막 성공 09-25 17:57 · 매일 작업 한도 36시간 넘김 · 다음 실행 2026-09-28 10:57"
  - 괄호가 없다. 같은 시각이 한 번만 나온다.
- monthly: "… — 첫 실행 없음 · 등록 08-10 20:47 뒤 매월 작업 한도 35일 넘김 · 다음 실행 2026-10-01 13:30"
  - 1999 날짜가 없다.
- tunnel: "… — 실패 · 결과 3221225477(0xC0000005) · 다음 실행 없음 · 마지막 실행 2026-09-16 05:24 뒤 278시간"
  - '다음 실행 없음'이 한 번만 나온다. 'N시간'에 기준 시각이 붙었다.
- **표 칩 + 사유 = 결재함 라벨:** 6행 모두 글자로 대조했다. 모두 같다.
  - 예: 터널 칩 '실패' + 사유 '결과 3221225477(0xC0000005) · 다음 실행 없음'
- **경계 자르기:** `org_runtime.clip_line` 을 읽었다.
  - ① ` · ` 경계
  - ② 공백 경계 — `_TS_SPAN` 으로 시각 안의 공백은 자르지 않는다
  - ③ 숫자 사이 회피
  - 다만 캡처의 목적 줄은 모두 140자 미만이다. 그래서 **'…' 로 끝나는 모습은 화면으로 미검증**이다. backend 는 운영 인계 4장이 공백 경계에서 '…' 로 끝난다고 적었다(내게 미검증).

## ② 물은 것에 대한 답

### 2-1. 주황은 한 뜻인가 · 빨강은 고장뿐인가 · 대기 톤 · 타일과 표

- **표의 주황:** 한 뜻이다(위 #2).
- **표의 빨강**
  - after-sched-1440·after-stopped-sched-1440 의 빨강은 '실패'(터널)·'꺼짐(Disabled)'·'다음 실행 없음' 셋뿐이다.
  - 넷째인 '실행된 적 없음'(+ 사유 '예정도 없음')은 캡처에 없어 **화면 미검증**이다. `schedState` 의 `v.broken` 분기와 `v == null` 원자료 분기에서 빨강인 것만 읽었다.
- **결재함과 겹쳐 보기**
  - 결재함의 '예약 작업 경보' 6장(주황 사유 라벨)은 표에서 빨강 3 + 주황 3 으로 나뉜다.
  - 이것은 모순이 아니다. `.ord .rs.warn` 위 주석의 규칙대로다: "빨강은 사실 판정 … 에만 쓰고 지시서 사유(결정 대기)에는 쓰지 않는다".
  - 결재함 경보 가운데 표에서 초록·무채색인 것은 **0** 이다. 1회차부터 이어온 모순이 닫혔다.
- **대기 톤:** 같다.
  - after-inbox-1440 의 '대기' 칩과 after-sched-1440 의 '아직 때가 안 됨' 칩은 모양과 색이 같다.
  - '확인 불가'(테두리, #b6c6d8)가 대기보다 한 단 무겁다. "정상 < 확인 불가 < 이상 < 멈춤" 원칙과 맞다.
- **타일 ↔ 표**
  - after-kpis-1440 부제: "1개 실패 · 1개 꺼짐(Disabled) · 1개 다음 실행 없음 · 1개 첫 실행 없음 · 2개 조용히 안 돎 · 1개 확인 불가". 표 칩의 글자·수와 같다.
  - stopped 데이터(before/after-stopped-kpis-1440):
    - 수정 전: 중립 "1개는 첫 실행 대기(예정일 있음)"
    - 수정 후: 빨강 "1개 꺼짐(Disabled) · 1개 다음 실행 없음" — 표의 빨강 2행과 같다.
- **글자 크기·색·굵기**
  - 칩(11px/600)이 먼저 서고, 사유(10.5px, --soft, 보통 굵기)가 따라온다. 조화롭다.
  - 빨강 칩이 '실패' 두 글자로 짧아졌다. r2 의 붉은 긴 띠('실패 · 결과 3221225477')가 사라져 표 안의 빨강 면적이 줄었다. 좋아졌다.
- **새 흠:** 타일 부제의 줄 머리 '·' → 아래 #1.

- '·' 가 혼자 서거나 줄 머리에 선 곳: **0** 이다. 네 폭 캡처를 모두 눈으로 봤고, measure `lonely` 도 0 이다.

## ⑤ 잘된 점

1. **1회차부터 이어온 모순이 끝까지 닫혔다.**
   - 결재함 경보 6장 → 표 빨강 3 + 주황 3, 초록·무채색 0.
   - before-sched-1440 에서 초록 '정상'이던 x-disabled·x-no-next 가 after 에서 빨강이다.
   - 판정을 다시 짜지 않고 `verdict`·`silence` 를 읽기만 한다.
2. **칩 머리 + 사유 = 결재함 라벨 글자, 이것을 고장 행까지 넓혔다.**
   - 빨강 칩이 두 글자로 짧아져 320px 표가 크게 짧아졌다. before/after-sched-320 을 나란히 보면 분명하다. 높이 2332→1484 는 frontend 측정이다.
3. **캡처로 결함을 두 번 잡아 고쳤고, 그 판을 attempt1·attempt2 로 남겼다.**
   - 내가 열어 봤더니 적힌 대로였다.
   - '숫자 갈림' 측정 계수를 더했고, 그 계수가 공허하지 않은지 변이로 확인했다.
4. **지시문과 다르게 읽은 두 곳을 숨기지 않았다.** 이유·되돌리는 방법·변이 테스트까지 적었다. 둘 다 동의한다.
   - verdict null 에서 silence.bad 를 주황으로 둔 것: 순환계가 이미 경보로 판정한 것이다. 회색으로 내리면 결재함은 주황, 표는 회색이 되어 1회차 모순의 반대편이 생긴다.
   - 확인 불가를 대기보다 먼저 본 것: 대기를 무채색으로 내린 이상, 모름을 대기로 칠하면 경보일지 모르는 것을 '괜찮다'고 말하게 된다. "모르는 것을 초록으로 그리지 않는다"의 연장이다.
5. **새 색을 만들지 않았다.** 결재함의 `pill idle`·`pill ok` 를 재사용해서, 두 표의 톤이 같은 사전에서 나온다.
