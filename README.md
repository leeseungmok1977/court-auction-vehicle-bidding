# 법원경매 차량 입찰가 산정 시스템

대법원 법원경매정보 차량 물건을 수집하고, **SK엔카 + 케이카(2차 소스) 시세를 교차검증**해 입찰가를 산정하는 시스템.
설계: [법원경매_차량_입찰가산정_통합설계서_v1.0.md](법원경매_차량_입찰가산정_통합설계서_v1.0.md) · 규칙: [CLAUDE.md](CLAUDE.md) · 디자인 시스템: [DESIGN.md](DESIGN.md)(Stripe 기반)

## 🖥️ 운영 웹도구 (권장 사용법)

Power Automate 대신 **파이썬 파이프라인 + 웹 대시보드**로 운영한다.

```bash
pip install -r requirements.txt      # 최초 1회
python run_web.py                    # 웹서버 실행 (포트 변경: python run_web.py 8080)
```
→ 브라우저에서 **http://127.0.0.1:8000** 접속

### 📅 매일 자동 갱신 (1개월 이내 입찰예정) — 권장 운영 방식

차종을 고르지 않고 **매각기일이 30일 이내인 전국 자동차 경매 물건 전체**를 매일 자동 갱신합니다.

1. 대시보드 **매일 자동 갱신** 패널에서 `자동 갱신 사용` 체크 + 실행 시각(예: 06:30) + 기간(30일) → 설정 저장
   (앱이 실행 중이면 내장 스케줄러가 매일 그 시각에 목록을 갱신)
2. `[지금 갱신]`으로 즉시 갱신도 가능. 갱신된 물건은 목록에 **미분석**으로 쌓임
3. `[국산차 시세 분석]`으로 국산차에 상세·엔카 시세·입찰가 산정을 일괄 적용
4. 대시보드 **입찰예정(30일)** 카드 또는 목록의 `입찰예정 30일만` 필터로 임박 물건 확인

**앱이 꺼져 있어도 매일 갱신**하려면 Windows 작업 스케줄러에 등록:
- 작업 스케줄러 → 작업 만들기 → 트리거: 매일 06:00 → 동작: [run_daily.bat](run_daily.bat) 시작
- 또는 수동 실행: `python -m web.daily 30` (30일 이내 입찰예정 갱신)

> 목록 갱신은 가볍습니다(페이지 순회만, 상세·시세 없음). 시세 분석은 소량·저속이라 필요한 만큼만 실행하세요.
> 기존 분석 결과·관심·메모는 갱신해도 보존됩니다.

- 데이터는 `data/auction.db`(SQLite)에 저장되어 재실행해도 유지됨.
- 수집은 백그라운드로 돌고, 대시보드가 2초마다 진행률을 갱신 → 완료 시 자동 새로고침.

### 🔎 시세 신뢰도 + 케이카 2차 소스 교차검증

시세는 단순 중앙값이 아니라 **신뢰도(0~100, 높음/보통/낮음)** 를 함께 산출한다 — 표본수·가격분산(CV)·매칭단계(동급→확장)·이상치(IQR)·감정가 정합·트림/세대/연료 확인을 종합.

- **케이카 2차 소스**: SK엔카 단일 소스의 편향을 걸러내기 위해 **케이카**(Playwright 인터셉션, `/bc/search/list/drct`)에서 동급 중앙값을 가져와 교차검증한다.
  - 두 소스가 ±10% 이내 **일치**하면 단일소스 상한(88)을 풀어 신뢰도 상향(최대 96), 크게 벌어지면 **불일치 경고**.
  - **분석·재교정 시 자동으로 함께 조회**(config `kcar_cross_enabled: true`). (모델·연식·연료) 캐시 + 요청 상한(`kcar_max_requests`)으로 부하 통제.
  - 개별 상세에서 **[케이카 2차 소스로 교차검증]** 버튼으로 온디맨드 실행도 가능.
- **실측 검증(백테스트)**: 실제 낙찰가와 대조해 **예상낙찰가**(=시세×과거 낙찰률)와 오차(MAE)를 대시보드에 정직하게 공개.
- **실측 캘리브레이션**: 상세에서 사용자가 확인한 실측 시세를 입력하면 시스템 시세 오차를 기록.

> 케이카 필드매핑 확인/문제 진단: `python run_kcar_discover.py [검색어]` (필요시 `--manual`/`--dom`).
